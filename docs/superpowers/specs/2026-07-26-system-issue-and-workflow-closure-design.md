# Fluxa 系统异常闭环与日常页面收口设计

日期：2026-07-26
状态：已纳入用户硬约束，待书面复核
范围：秒传失败、追更生效结果、发现页收口、RSS 资源语义、任务快照、活动记录、移动异常入口、设置分组

## 1. 背景与目标

当前页面已经具备基本状态汇总和移动适配，但部分信息仍停留在“看见异常”而不是“理解原因并完成处理”。本轮目标是建立以下闭环：

1. 首页秒传状态可以准确定位到分类级事实、自动恢复计划和下一步动作。
2. 加入追更后直接显示真实生效结果，不再根据后台扫描状态猜测。
3. 发现页只负责找片和加入追更，完整追更管理回到追更页。
4. RSS 资源统计、预览和安全边界使用可验证事实，不暗示不存在的下载或入库状态。
5. 任务统计变化、活动记录和移动端异常入口保持连续、可解释、可分享。
6. 设置页默认只展示家庭用户常用能力，其余配置进入高级设置。

本轮保留现有克制的工业控制台风格，不重做品牌、影院大厅或全局视觉语言。

## 2. 已确认事实

### 2.1 Torra 秒传证据

实机当前可读取到：

- 12:00 批次共 8 个分类，失败分类为 `00-日漫`，成功 0、失败 1；
- 06:00 同分类成功 6、失败 1；
- 00:00 同分类成功 4、失败 3；
- 下一轮计划时间为 18:00；
- 插件策略为失败 3 次后转原始上传，失败 3 次后通知。

Torra 当前插件批次响应没有返回失败文件名、具体错误、单文件累计重试次数或可关联的 job ID。近期成功 job 虽然包含逐文件字段，但不能用其他成功任务推断当前失败文件。

Torra 已确认存在正式手动任务接口：

```text
POST /api/v1/plugins/{pluginKey}/tasks/{taskKey}/run
```

本轮不挂载 Torra SQLite，不读取 Torra 私有目录，也不从 Symedia、qB、115 或标题反推文件级秒传事实。

### 2.2 手动加入追更

保存追更后，后端会立即根据当前模式决定是否进入 Torra、MoviePilot、Symedia 或资源处理队列。后台订阅扫描器只负责定时读取自动来源，不决定一次手动加入是否生效。

当前兼容保存接口丢弃了真实的 `subscription_task`，前端又使用 `scheduler.running` 猜测手动加入结果，因此会出现“仅保存”和“自动获取”文案互相矛盾。

### 2.3 RSS 资源

`hasDownload` 只表示 RSS 数据库保留了可供服务端使用的下载信息，不表示已经下载。浏览器不得获得下载地址、详情地址、Cookie 或 Passkey。

当前 `1/1 集` 来自同一个集号集合同时作为分子和分母，且季包没有进入统计，因此没有业务意义。

## 3. 方案选择

### 3.1 方案 A：仅修改前端文案

优点是改动小。缺点是无法修正秒传红色状态、追更排队结果、活动记录截断和 RSS 统计口径，仍会继续展示错误事实。

### 3.2 方案 B：兼容契约扩展与页面收口

后端补充安全、可选的新字段，前端按真实状态展示；不更改现有主路由和旧字段。秒传使用分类级证据和 Torra schedule，追更返回明确 activation，活动记录在截断前折叠。

这是本轮采用的方案。

### 3.3 方案 C：挂载 Torra 数据库并建立完整文件台账

可能获得更细证据，但会引入跨容器数据库耦合、路径配置、schema 兼容和部署风险。当前还没有验证 Torra 数据库能否提供所需字段，因此不纳入本轮。

## 4. 秒传状态机

### 4.1 固定判定常量

```text
SCHEDULE_GRACE_SECONDS = 600
MAX_SCHEDULE_HORIZON_SECONDS = 86400
```

- 宽限时间固定为 10 分钟。计划时间过去不超过 10 分钟时仍视为等待任务启动。
- 合理计划周期固定为 24 小时。下一次计划超过当前时间 24 小时，不得用来维持“待恢复”。
- 所有时间先解析为带时区的绝对时间，再统一以北京时间显示。跨天不得只比较时分。

### 4.2 状态判定

状态只允许：

```text
normal | recovering | action_required | unknown
```

判定顺序：

1. Torra 或插件读取失败、关键字段缺失时为 `unknown`，不把未知事实染成红色。
2. 最近批次失败数为 0 时为 `normal`。
3. 存在活动中的秒传运行时为 `recovering`。
4. 最近批次失败数大于 0 时，只有同时满足以下条件才为 `recovering`：
   - 插件已启用且可读取；
   - `retry_pending` 任务允许自动调度；
   - 对应 schedule 已启用；
   - `nextRunAt` 可解析；
   - `nextRunAt >= now - 10 分钟`；
   - `nextRunAt <= now + 24 小时`。
5. 已确认有失败，但没有活动任务，也没有满足全部条件的自动恢复计划时为 `action_required`。

不得只凭 `nextRunAt` 非空判断“待恢复”。

### 4.3 分类批次详情

公开响应增加分类级安全摘要：

```json
{
  "state": "recovering",
  "stateReason": "scheduled_retry",
  "failedTotal": 1,
  "nextRunAt": "2026-07-26T18:00:00+08:00",
  "scheduleGraceSeconds": 600,
  "categories": [
    {
      "id": "category:4f7c9a2d5b10",
      "label": "00-日漫",
      "latest": {"success": 0, "failed": 1, "finishedAt": "2026-07-26T12:02:00+08:00"},
      "recentFailedCounts": [3, 1, 1],
      "retryPolicyText": "失败 3 次后转原始上传",
      "fileEvidenceAvailable": false
    }
  ]
}
```

页面文案固定为：

```text
近三批失败数：3 → 1 → 1
```

必须明确这是分类批次统计，不能暗示三批处理的是同一个文件。

公共响应不得包含 Torra 原始分类 ID、插件 key、源目录、目标目录、文件路径、下载地址或配置值。分类公开 ID 使用稳定摘要。

### 4.4 首页与任务中心

首页关注项链接改为：

```text
/tasks?systemIssue=secupload_failures
```

状态为 `recovering` 时，首页显示“秒传待恢复 1”，使用处理中语义，不进入红色真实异常计数。状态为 `action_required` 时才显示“秒传需要处理 1”。

任务中心增加独立的系统问题面板，不把分类批次伪装成媒体任务卡。当前实机应显示：

```text
00-日漫正在自动恢复
本批失败 1
近三批失败数：3 → 1 → 1
下次自动重试：今天 18:00
失败 3 次后转原始上传
```

同时固定显示能力说明：

```text
Torra 当前未返回失败文件名、具体错误和单文件重试次数。
```

### 4.5 手动重试边界

自动重试有效时，主操作是非危险状态动作“等待 18:00 自动重试”。手动运行只出现在高级操作，且在自动计划有效或已有活动运行时禁用，防止重复触发。

只有 `action_required` 且 Torra 明确声明 `retry_pending.allowManualRun=true` 时，主操作才允许变为“重试失败队列”。执行必须具备：

1. 预检：重新读取插件状态、分类映射、活动运行和 schedule；
2. 明确确认；
3. 12 至 128 字符幂等键；
4. 全局 Torra 秒传运行锁与分类锁；
5. 使用现有 `provider_actions` 持久化动作；
6. Torra 返回 run ID 后保存为 `external_job_id`；
7. 通过插件 `recent_runs` 轮询该 run ID，显示已收到、执行中、成功或失败；
8. 上游接口失败时写入脱敏活动记录并释放租约；
9. 相同幂等键返回原动作，相同分类的竞争动作返回 409；
10. 执行结束后重新读取分类批次和自动计划，不依赖前端乐观更新。

## 5. 追更生效契约

### 5.1 能力拆分

能力接口将现有混合状态拆为：

```json
{
  "manualFollow": {
    "state": "write_disabled|saved_only|queued_ready",
    "provider": "torra|moviepilot|symedia|resource_rule|none",
    "blockers": []
  },
  "sourceScan": {
    "configured": true,
    "enabled": false,
    "running": false
  }
}
```

`sourceScan` 只描述后台来源扫描，不参与手动加入结果判定。

### 5.2 保存结果

保存接口增加可选 `activation`：

```text
saved_and_torra_pushed
saved_and_queued
saved_only
already_exists
saved_push_failed
```

每个结果包含稳定 `state`、用户文案、provider、是否进入队列和脱敏原因。含义如下：

- `saved_and_torra_pushed`：Torra 已明确确认创建或已有远端关联；
- `saved_and_queued`：Fluxa 已保存且后台动作已经成功入队；
- `saved_only`：只保存到 Fluxa，没有可运行的后续能力；
- `already_exists`：同一媒体和范围已经存在，不重复创建；
- `saved_push_failed`：Fluxa 保存成功，但同步提交明确失败。

异步动作仅在入队时返回 `saved_and_queued`，不得提前写成“已推送 Torra”。后续结果由动作状态刷新。

### 5.3 页面文案

- 写入关闭：按钮显示“追更写入已关闭”。
- 只能保存：按钮显示“加入追更（仅保存）”。
- 后续能力可用：按钮显示“加入追更”。
- 普通页面统一使用“追更”；Torra“订阅”只保留在高级诊断。
- 保存成功提示直接展示 `activation.message`，不得统一提示“订阅成功”。

## 6. 发现页收口

发现页右侧只显示最近更新的 3 条追更和“查看全部追更”。每条保留作品、范围、当前真实状态和指向 `/following?subscriptionId={subscriptionId}` 的深链。

发现视图不渲染：

- 完整追更列表；
- 电影/电视剧/屏蔽 tabs；
- 1900 至当前年份的年份筛选；
- 更新来源、删除、屏蔽、Torra 对账和质量观察操作。

完整管理继续放在追更页。发现页可以保留轻量身份集合，用于判断搜索结果是否已经追更，但 DOM 中最多出现 3 条最近追更。

## 7. RSS 统计与资源预览

### 7.1 互斥资源分类

每条资源只允许进入以下一个分类：

1. `explicit_episode`：季号已确认，且只包含一个明确集号；
2. `season_pack`：季号已确认，没有明确集号，且季范围状态已确认；
3. `scope_pending`：多集范围、季号缺失、季范围未知或其他无法归入前两类的资源。

必须满足：

```text
明确单集 + 季包 + 范围待确认 = 资源总数
```

页面显示“5 个资源 · 明确单集 1 · 季包 1 · 范围待确认 3”，不再显示 `x/y 集`。只有取得作品官方总集数并且统计口径明确时，才允许另行展示覆盖率。

### 7.2 预览信息

预览展示：

- 匹配原因：TMDB 精确、标题与类型/季号匹配，或回退匹配；
- 资源范围：明确单集、季包或范围待确认；
- 官种：没有可靠证据时显示“无法判断”；
- 下载、入库、重复：没有逐资源归属证据时显示“尚未确认”；
- 当前处理状态：未处理、已建立匹配、Torra 分析中或 Torra 已接收；
- 优先检查理由：精确身份优先、明确季集优先；最终下载推荐只来自 Torra 分析评分。

页面和 DTO 中不再使用“下载入口”“可下载”“已保留下载信息”等容易误解的普通文案。

当服务端保存了下载信息时，普通操作显示“交给 Torra 处理”；没有安全处理条件时只显示“查看识别证据”。Fluxa 浏览器端不得直接访问 PT 下载地址或私有详情页。

## 8. 任务快照与活动记录

### 8.1 快照变化

前端只在以下条件全部满足时比较前后快照：

- 两份响应统计口径相同；
- 都是全局汇总，不是分页、加载更多或局部筛选计数；
- `version` 确实变化；
- 响应不是 304；
- 当前页面没有切换用户状态、完成日期或身份筛选。

轮询中显示“数据更新中”。更新后显示最近快照时间和非零差值，例如“较上次：无需处理减少 5”。只有后端 `ledger.artifactMigrations > 0` 时才显示“本轮已整理 N 个历史产物身份”。普通下载变化不得写成身份整理。

### 8.2 活动折叠

活动 API 在应用 `limit` 前提供重点视图：

- 仅折叠 `request_id=background`、状态为 success/info/skip、且 category/action/status 相同的后台活动；
- error 和人工请求永不折叠；
- 折叠项返回 `repeatCount`、`firstTime`、`lastTime`；
- 默认展示重点活动，保留“全部原始记录”切换；
- 活动类型和视图写入 URL。

原始接口行为保持兼容。

## 9. 移动端异常入口

五栏主导航的“任务中心”增加异常数字角标，仅在 `actionRequired > 0` 时显示，最大显示 `99+`。点击异常角标或异常状态下的任务入口直接进入：

```text
/tasks?userState=action_required
```

摘要读取失败时不显示红色角标。角标不得改变五等分导航宽度或覆盖选中指示器。

首页“查看任务中心”在窄屏显示为“任务中心”，保持单行；320、360、390、430 像素宽度都不得重叠。

## 10. 设置页信息架构

默认只展示四组：

- 连接：Emby、qBittorrent、Torra、Symedia、TMDB 的核心地址和凭据；
- 自动化：追更扫描、Torra 同步、RSS、质量观察、推送和云盘能力；
- 通知：Telegram Bot、会话和订阅/转存通知；
- 安全：写入开关、外部管理权限和访问保护。

其余字段只出现于“高级设置”，同一字段不得同时出现在常用与高级区域。移除“96 项可编辑”，改为“常用设置”。搜索仍覆盖全部字段并自动展开命中分组。

保存仍按实际 dirty key 提交；敏感值不回显；重启提示保留。连接验证按变更字段前缀确定受影响服务，不依赖展示分组 ID。

## 11. 错误处理与安全边界

1. Torra 部分字段缺失时降级为 `unknown`，展示缺失事实，不猜测。
2. Torra 临时失败保留上一份有时间戳的只读快照，并明确标记已过期；不得继续显示为实时状态。
3. 所有新字段均为兼容性可选字段；旧客户端继续使用现有字段。
4. 浏览器响应、活动记录和错误信息不得包含下载地址、详情地址、Passkey、Cookie、Token、文件路径或 Torra 原始私有 ID。
5. 本轮自动化测试不得触发真实 Torra、qB、115、Symedia 或 Emby 写操作。

## 12. 测试与验收

### 12.1 秒传

- `nextRunAt` 同日、跨天、UTC 与北京时间转换；
- 计划时间前、逾期 9 分钟、逾期 10 分钟和逾期 11 分钟；
- 下一计划超过 24 小时；
- 自动调度关闭、schedule 关闭、任务不允许 schedule；
- Torra 字段缺失、不可达和响应结构无效；
- 两次点击同一幂等键返回同一动作；
- 不同幂等键竞争活动锁返回 409；
- 预检失败不调用 Torra 写接口；
- 执行后按 run ID 跟踪并重新读取分类状态；
- 公共响应不泄露目录、原始分类 ID 或文件路径。

### 12.2 追更

- 写入关闭；
- 写入开启、Torra 推送关闭；
- Torra 推送开启、后台扫描停止，手动加入仍可入队；
- 已存在目标不重复创建；
- Fluxa 保存成功但推送明确失败；
- 页面逐项对应五种 activation 文案。

### 12.3 RSS

- 同季 5 条混合资源覆盖明确单集、季包、多集范围、季号缺失和范围未知；
- 三类互斥计数之和等于资源总数；
- 页面不出现 `1/1 集`；
- TMDB 精确、标题回退和季号未知的匹配原因；
- 官种、下载、入库和重复默认不得伪造；
- HTML、JSON、日志和浏览器网络响应绝不出现下载地址、详情地址或 Passkey。

### 12.4 任务、活动、移动端和设置

- 快照差值只比较相同统计口径；
- 首次加载、304、加载更多、筛选切换和服务重启不误报差值；
- 200 条重复后台同步不能挤掉更早的人工失败；
- 深浅主题、键盘焦点、Escape 关闭和 Tab 顺序；
- 320、360、390、430、768、1440 视口；
- 手机异常角标准确跳转并保留 URL；
- 设置字段不重复、敏感值不回显、分组保存只提交 dirty key。

## 13. 实施顺序

1. 秒传安全摘要、状态机、系统问题深链和任务面板；
2. 追更 capabilities 与 activation 契约；
3. 发现页最近 3 条收口；
4. RSS 互斥统计和证据预览；
5. 活动重点视图与任务快照差值；
6. 移动异常角标和设置四组；
7. 文档、契约、完整测试、浏览器回归、Git 与镜像发布；
8. fnOS 拉取重建、revision 核对和实机回归；
9. 全部通过后直接关闭计算机，不再二次确认。
