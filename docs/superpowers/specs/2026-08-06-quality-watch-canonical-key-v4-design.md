# 质量观察规范键迁移与桥接 v4 设计

日期：2026-08-06

状态：已确认

实施边界：只修改 Fluxa；不修改 Torra、qB 或 Symedia；不触发搜索、下载、秒传、归档或历史初始化；自动下载继续关闭。

## 1. 目标

Fluxa 内部必须只使用一个 Torra 订阅身份：`torra:<远端ID>`。`torra:<10位摘要>` 仅是 API、界面和公开日志中的脱敏投影，不再作为观察单元、RSS 匹配、操作台账或调度游标的内部主键。

本次变更同时完成：

- 将已有公开短键观察事实一次性迁移到规范内部键；
- 让桥接器、质量观察调度器和 RSS 匹配器复用同一个订阅解析器；
- 将生产桥接协议升级为 v4，并保留 v3 收据作为历史审计；
- 用完整集成测试验证 Torra 只读订阅从生产事实到质量面板始终属于同一目标。

## 2. 方案选择

采用启动前严格迁移。

应用在 SQLite 相关 schema 初始化完成后、桥接器和质量观察调度器注册前执行迁移。迁移成功后才允许继续启动服务；发现规范键与公开短键同时存在时，整批迁移中止、事务全部回滚并阻止启动。

不采用以下方案：

- 管理员手动迁移：会留下新旧键并存的运行窗口，期间可能重复创建观察单元或错误领取动作。
- 懒迁移或长期双键兼容：会让幂等、RSS 所有权和调度游标继续依赖两套内部身份，无法保证事实唯一性。

即使冲突单元字段完全一致，也不得自动合并。观察单元之外的 RSS 匹配、操作记录、版本号和幂等状态可能不同，自动合并可能造成重复洗版或错误归属。

## 3. 内部键与公开键

### 3.1 规范内部键

Torra 只读订阅的规范键固定为：

```text
torra:<远端ID>
```

观察单元键继续由规范订阅键派生，例如：

```text
torra:<远端ID>:s1:e4
```

Fluxa 本地订阅继续使用现有本地订阅键，不迁移为 Torra 键。本地订阅与 Torra 只读订阅的优先级、只读边界和远端绑定校验保持不变。

### 3.2 公开短键

公开短键继续由远端 ID 的稳定摘要生成：

```text
torra:<10位摘要>
```

API 请求可以继续接受公开短键；API 响应、界面、活动结果、错误文本和冲突报告只能返回公开短键或独立脱敏目标引用。原始 Torra ID 和规范内部键不得进入公开响应。

公开键转换集中在契约映射和公开投影边界。桥接、调度、RSS 评分、动作领取和数据库关联不得把公开短键当作内部身份。

## 4. 统一订阅解析器

`QualityWatchSubscriptionResolver` 同时读取 Fluxa 本地订阅和 Torra 只读订阅，并为已解析目标返回：

- `canonicalKey`：内部规范键；
- `publicKey`：公开短键；
- `subscriptionKey`：内部实际所有者键，本地订阅使用本地键，Torra-only 使用规范 Torra 键；
- 只读订阅事实和明确的来源标记。

解析只使用 Torra ID、TMDB ID、媒体类型和季号。四项必须完整、唯一且一致；标题、别名和模糊相似度不得参与身份绑定。存在重复远端 ID、TMDB/类型/季冲突或所有权不唯一时保持不可解析。

桥接器、质量观察调度器和 RSS 匹配器必须复用同一个解析器及同一套合并规则：

- 本地订阅优先，但必须与远端绑定和媒体身份一致；
- 没有本地订阅时允许使用 Torra-only 只读事实；
- Torra-only 不写入 Fluxa 本地订阅表，不形成第二套订阅事实；
- 外部动作前继续实时核验 Torra 当前订阅，不能因为本地解析快照而放宽预检。

## 5. 启动迁移

### 5.1 启动顺序

迁移位于以下顺序中：

1. 初始化统一 SQLite runtime、质量观察表和 Private RSS 表；
2. 只读生成迁移计划；
3. 没有待迁移数据时直接返回 0，不创建新备份；
4. 有待迁移数据时创建并校验 SQLite 备份；
5. 在单一 `BEGIN IMMEDIATE` 事务内重新生成关键事实、校验计划指纹并应用计划；
6. 迁移成功后注册桥接器、自动化服务和质量观察调度器；
7. 将当前桥接协议切换到 v4。

备份失败、完整性校验失败、迁移冲突或事务失败都必须阻止服务启动。不得在迁移失败后继续注册任务快照桥接或质量观察调度。

### 5.2 映射依据

迁移映射只能来自本地业务行中唯一、明确的 `torra_subscription_id`。迁移器必须先验证旧公开键确实等于该远端 ID 经 `torra_public_subscription_key()` 生成的摘要，再生成目标键：

```text
公开订阅键 -> torra:<远端ID>
公开单元键 -> make_unit_key(torra:<远端ID>, media_type, season, episode)
```

规范单元键必须使用统一 `make_unit_key()` 根据观察单元的媒体类型、季号和集号重新生成，禁止按字符串前缀直接替换。迁移器不得从 10 位摘要反推远端 ID，也不得通过标题、别名或相似度补齐映射。

同一个公开短键若对应多个不同远端 ID，即发生 10 位摘要碰撞。摘要碰撞必须返回冲突并阻止迁移和订阅解析，不能按列表顺序任选一条。缺少唯一远端 ID、摘要校验失败或单元结构字段不足的旧行同样不得猜测迁移，必须进入阻断冲突报告。

### 5.3 冲突检测

事务开始后重新读取并核验计划指纹。以下情况全部阻止整批迁移：

- 同一目标同时存在规范键观察单元与公开短键观察单元；
- 多个旧单元映射到同一个规范单元键；
- 同一个 10 位摘要对应多个不同 Torra 远端 ID；
- `rss_subscription_matches` 的迁移会违反 `UNIQUE(item_id, unit_key)`；
- 操作记录或调度状态无法唯一替换；
- 已登记 JSON 路径之外仍存在旧公开键引用；
- 计划生成后数据库事实发生漂移；
- 任何待迁移行缺少可靠、唯一的远端订阅身份。

发生冲突时不更新、不删除任何业务记录。主事务回滚后，使用数据库之外的 sidecar JSON 写入脱敏冲突报告；不在失败数据库内写审计，以满足业务库零修改要求。

### 5.4 原子更新范围

无冲突时，一个事务内统一更新：

- `quality_watch_units.subscription_key`；
- `quality_watch_units.unit_key`；
- `rss_subscription_matches.subscription_key`；
- `rss_subscription_matches.unit_key`；
- `provider_actions.subscription_key`；
- `provider_actions.unit_key`；
- 已登记的结构化 JSON 路径；
- 已知由系统生成且包含旧单元键的确定性 `idempotency_key`；
- `scheduler_state.payload_json` 中的 `cursor` 和 `lastSubscription`。

结构化 JSON 迁移使用固定登记表。允许精确改写的路径限定为：

- `provider_actions.request_summary_json.unitId`；
- `provider_actions.request_summary_json.subscriptionId`；
- `provider_actions.response_summary_json.unitId`；
- `provider_actions.response_summary_json.subscriptionId`；
- `scheduler_state.payload_json.cursor`；
- `scheduler_state.payload_json.lastSubscription`。

迁移器必须扫描下列全部相关 JSON 列：

- `quality_watch_units.current_evidence_json`；
- `quality_watch_units.last_result_json`；
- `provider_actions.request_summary_json`；
- `provider_actions.response_summary_json`；
- `rss_subscription_matches.match_reason_json`；
- `rss_subscription_matches.candidate_summary_json`；
- `rss_subscription_matches.baseline_summary_json`；
- `scheduler_state.payload_json`。

只有登记路径允许按 JSON 类型解析后精确改写。其余列当前没有允许迁移的键路径，只参与遗留引用扫描。禁止全文字符串替换。

扫描时如果旧公开键出现在未登记的 JSON 路径、数组位置或未知结构中，整批迁移必须中止并报告具体表、列、脱敏行引用和 JSON 路径。JSON 原文、远端 ID 和文件路径不得进入报告。

`action_id`、RSS match ID、外部 job ID、artifact key、版本号和 v3 桥接收据保持不变。未知格式的幂等键不得做模糊字符串替换；如果它明确引用待迁移键但不符合白名单格式，则阻止迁移并进入冲突报告。

迁移成功标记与业务更新在同一事务提交。重复启动时迁移更新数必须为 0，且不创建新备份或报告以外的重复业务记录。

### 5.5 备份与冲突报告

迁移前使用 SQLite backup API 创建同目录时间戳备份，并对备份执行 `PRAGMA integrity_check`。备份名称不包含远端 ID。

冲突报告至少包含：

- 迁移版本和发生时间；
- 稳定哈希化的 `targetRef`；
- 冲突原因码；
- 观察单元、RSS 匹配、操作记录和调度引用数量；
- 不含敏感字段的处理建议。

日志只输出相同的脱敏引用、关联数量和建议，不输出 Torra 原始 ID、规范内部键、文件路径、下载地址、Cookie 或 Passkey。

人工修复冲突后再次启动，迁移必须能从头重新生成计划并幂等完成。

## 6. 桥接 v4 与审计

生产桥接版本升级为 `4`。激活水位保持原值，不因升级、重启或重新启用而刷新。

v3 收据永久保留，不迁移、不删除。v4 使用新的收据键空间，设置页和桥接摘要只统计 v4；旧收据仍可通过技术审计读取。媒体结果、候选统计和质量面板基于唯一观察单元与 RSS 匹配，不跨版本累加收据数量。

迁移后的观察单元已经使用规范键。v4 重复处理相同 qB 或 Symedia 事实时，只能推进或修正同一单元，不能因为 v3/v4 收据空间不同而创建第二个单元。

收据与观察单元变更继续在同一 SQLite 事务内完成。外部 Torra、qB 和 Symedia 读取在事务外转换为本地版本化证据；桥接失败不得污染永久媒体事件。

## 7. 调度与 RSS 数据流

质量观察调度器每轮读取本地订阅和 Torra 只读订阅，通过统一解析器生成内部订阅映射。Torra-only 规范单元必须能找到对应只读订阅，不再因调度器只读取本地订阅而进入 `subscription_missing`。

Torra 订阅读取必须携带明确的采集结果。连接失败、认证失败、超时或响应不可解析时属于 `source_unavailable`：已有观察单元保持原状态、延后下一次处理并记录当前诊断，不得批量写成 `subscription_missing`。只有 Torra 成功返回可确认的完整订阅列表，并且规范目标确实不在列表中时，才允许认定 `subscription_missing`。

RSS 回扫、候选评分和冠军选择使用同一规范订阅键及规范单元键。范围包仍可投影到多个集级单元，但一个 artifact 只有一个规范订阅所有者，底层评分与下载动作仍保持一次。

API 和界面查询公开短键时，入口先解析为规范内部键；返回结果再投影为公开短键。兼容查询不得在数据库中同时保存两套键。

## 8. 错误处理与启动门禁

- 备份失败：不进入迁移事务，启动失败；
- 计划冲突：业务库零修改，写脱敏 sidecar 报告，启动失败；
- 事务校验漂移：整批回滚，写脱敏报告，启动失败；
- 事务执行失败：整批回滚，保留原数据库和备份，启动失败；
- 报告写入失败：仍然启动失败，并只输出不含敏感内容的最小日志；
- 无待迁移数据：返回 0 更新，继续启动；
- Torra 临时离线：不改变已有观察单元结论，延后处理；
- 修复冲突后重启：重新计划、重新校验并幂等迁移。

任何失败路径都不得注册桥接写入、调度器或后台 RSS 洗版运行时。

## 9. API 兼容与安全

- 不删除字段、不修改现有字段类型、不新增必填请求字段；
- API 请求继续接受公开短键；
- API 响应继续只返回公开短键；
- 规范键和远端 ID 不进入公开错误、活动记录或质量面板；
- 自动下载、Torra 搜索、订阅修改和历史初始化保持关闭或不触发。

## 10. 测试与验收

完整集成测试使用临时 SQLite 和模拟 Torra/qB，不访问生产数据库或真实外部服务。

### 10.1 迁移成功路径

1. 建立 pre-v4 公开短键观察单元、RSS 匹配、操作记录、调度游标和 v3 收据；
2. 运行迁移并验证备份存在、`integrity_check` 通过；
3. 验证观察单元、RSS、操作记录、白名单幂等键和调度游标全部切换为规范键；
4. 验证 action ID、match ID、artifact、版本号和 v3 收据保持不变；
5. 验证全部相关 JSON 列中不存在遗留公开键，且已登记字段被结构化迁移；
6. 第二次运行迁移更新数为 0，且无待迁移时不产生新备份。

### 10.2 端到端生产链

1. Torra-only 只读订阅通过 v4 桥接处理 qB/Symedia 事实；
2. 已迁移单元被推进而不是重复创建；
3. 调度器可以找到同一规范订阅；
4. RSS 回扫和评分绑定同一规范单元；
5. 质量面板与 RSS API 只返回公开短键；
6. 手工洗版和手工 RSS 匹配新建的记录只保存规范内部键；
7. Torra 临时离线时已有观察单元保持原状态，不被标记为订阅缺失；
8. 重复快照不增加单元、匹配或动作。

覆盖路径固定为：

```text
Torra 只读订阅 -> 生产桥接 v4 -> 质量观察调度 -> RSS 匹配/评分 -> 质量面板
```

### 10.3 冲突路径

建立同一目标的规范键和公开短键双单元，并关联不同 RSS、动作或版本状态。验证：

- 整批迁移回滚；
- 服务启动失败；
- 备份和脱敏冲突报告存在；
- 数据库业务记录逐行保持不变；
- 日志和报告不包含远端 ID 或规范键；
- 构造两个远端 ID 映射到同一 10 位摘要时，解析和迁移均拒绝继续；
- 未登记 JSON 路径含旧键时，迁移拒绝继续且业务库零修改；
- 删除或修复冲突后，重复启动可幂等迁移成功。

### 10.4 回归门禁

- 运行迁移、订阅解析、桥接、调度、RSS 和质量面板专项测试；
- 运行后端全量测试；
- 运行前端类型检查和生产构建；
- 运行 `git diff --check`；
- 检查 README、DESIGN、API 契约和计划文档是否同步；
- 确认未跟踪的本地 SQLite 样本未被修改或提交。

## 11. 完成标准

- 内部数据库不再新增公开短键观察事实；
- 旧公开短键事实可在无冲突时一次性原子迁移；
- 任意双键冲突都会回滚并阻止启动；
- Torra-only 订阅贯穿桥接、调度、RSS 和质量面板时始终属于同一规范目标；
- v3 审计保留，v4 摘要不重复统计；
- 公开 API、界面、日志和冲突报告不泄露 Torra 原始 ID 或规范内部键；
- 自动下载、搜索和外部写操作没有被启用。
