# Fluxa 手机端日历与控制室收尾设计

日期：2026-07-25
状态：已实施

## 背景

实机检查确认后端日历摘要和日期详情已经返回 `posterUrl`，但手机月视图通过 CSS 隐藏了全部日历条目，日期详情也没有渲染海报。控制室的右侧事实列表缺少基础布局，首次请求尚未返回时又把空值当成“未配置”，因此出现“连接状态 / 在线 / 最近检查”等信息挤在一起，以及短暂的 `0 / 4 在线` 错误结论。

同时复查窄屏页面后发现，任务工具栏和追更条目的操作区仍保留桌面横排；直接调用 `crypto.randomUUID()`、`Array.at()` 和未保护的 `localStorage` 也会在部分 HTTP、旧版或受限手机浏览器中中断交互。

## 设计目标

- 390px 宽度下不产生页面级横向溢出或控件重叠。
- 手机月视图保留 7 列日期结构，并为有内容的日期显示一张可点击海报、状态点和数量。
- 日期详情使用海报、标题、季集和健康状态组成稳定的三列头部；窄屏时健康状态换到标题下方。
- 控制室先显示真实加载态，接口完成后再计算在线、异常和未配置数量。
- 控制室事实字段使用服务专属标签，不再使用“运行信息 / 补充信息”。
- 服务卡在手机端变成横向服务选择条，详情紧随其后，避免四张大卡纵向堆叠。
- 不修改日历和订阅的数据事实源，不新增外部写操作。

## 组件与数据流

### 日历

后端继续通过 `/api/v2/calendar?view=summary` 返回每天最多三条预览，摘要和日期详情都保持 `posterUrl`。前端月视图在手机断点隐藏完整标题条目，但把当前筛选下的第一张海报放入日期摘要按钮；没有匹配预览时回退到该日第一条预览。桌面和周视图继续显示标题条目，只放大缩略图并限制标题溢出。

日期详情复用 `EntryPoster`，图片失败时沿用稳定首字占位，不出现裂图。

### 控制室

`servicesLoaded` 只表示第一轮并发读取已经结束。读取前四项服务状态均为 `loading`，不会参与在线、异常或未配置统计；读取结束但某接口没有返回时显示“读取失败”，而不是猜测为未配置。

每个服务模型携带结构化 `facts`：Torra 显示完成情况与搜索任务，qB 显示上传速度与卡住任务，Symedia 显示今日结果以及异常或最近记录，Emby 显示媒体库状态与近期索引。

### 手机布局

- 日历筛选栏纵向排列，日期格内使用 30×44 海报。
- 控制室服务卡横向滚动并设置滚动吸附，详情面板占满一列。
- 追更标题允许两行，操作按钮单独占第二行。
- 任务筛选标签和操作区上下排列。
- 工作页直接子项和 Hero 子项统一 `min-width: 0`，允许网格、弹性项正确收缩。

## 兼容与错误处理

- 幂等键优先使用 `randomUUID`，缺失时依次降级到 `getRandomValues` 和时间戳随机组合。
- 不再使用 ES2022 `Array.at()`。
- 主题和影院偏好通过安全存储工具读写；浏览器禁用存储时保留当前会话状态，不让页面初始化失败。
- 剪贴板调用继续保留现有异常提示。

## 验收

- TypeScript 类型检查和 Vite 生产构建通过。
- 日历后端测试明确断言摘要预览与日期详情都保留 `posterUrl`。
- Torra 导入、仓储事务和幂等回放定向回归通过。
- 390×844 静态实测页面宽度不超过视口，日历海报可见，控制室、追更和任务工具栏无重叠。
- 发布后在实机重新执行 Torra 镜像导入，并确认“仅 Torra”降为 0。

## 非目标

- 不改变 Torra 单向镜像的只读边界。
- 不在控制室增加高风险文件操作。
- 不修改影院大厅的沉浸视觉结构。
- 不用季级证据推断单集已经获取或入库。
