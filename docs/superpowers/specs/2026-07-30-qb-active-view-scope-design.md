# qB 活跃任务专用视图收口设计

## 目标

消除首页与任务中心 qB 专用视图中的口径误读。该改动只调整前端文案和条件展示，不修改后端统计、API、任务事实、筛选语义或历史事件。

## 首页文案

首页所有面向用户的当前下载数量统一称为“qB 活跃任务”。摘要行、指标卡片和焦点项不得再出现“qB 下载任务”这一计数名称。

后端继续返回现有 `activeDownloadTasks` 字段；前端只统一显示名称，不改变在线零值与未知态规则：

- qB 在线且明确返回 `0`：显示 `0`；
- qB 离线、读取失败或计数无效：显示“未知”，不得显示 `0`。

## qB 专用视图

当 URL 包含 `qbActive=1` 时，任务中心进入 qB 当前活跃任务专用视图。

### 保留内容

- `qB 当前活跃任务 N 个 · M 条媒体链`；
- qB 活跃任务关联的媒体链列表；
- 同一媒体链的并发 qB 任务说明；
- 刷新操作；
- “查看全部任务”入口。

活跃任务数与媒体链数必须分别保留。例如两个 qB 任务归入同一目标时，显示“qB 当前活跃任务 2 个 · 1 条媒体链”。

### 隐藏内容

- “处理中 / 需要处理 / 已可播放 / 无需处理”四项全库状态统计；
- 对应的四个全库筛选标签；
- 全局“需要处理”“已可播放”等任务摘要；
- 与当前 qB 活跃任务筛选无关的 Torra 秒传系统问题；
- 全库“最近活动”。

专用视图只回答“qB 当前有多少活跃任务，以及它们关联到哪些媒体链”，不得混入全库媒体结果或全局操作记录。

## 返回普通任务中心

点击“查看全部任务”后清除 `qbActive` 查询参数，恢复普通任务中心的全部状态统计、筛选标签、系统问题和最近活动。普通 `/tasks` 页面现有行为与布局保持不变。

浏览器刷新时继续从 URL 恢复 `qbActive=1`，不得退回普通任务中心。

## 数据与兼容边界

- 不新增或修改 API；
- 不修改 `counts.active`、`qbControl.active`、媒体链结果或分页逻辑；
- 不修改 qB 15 分钟观察窗和未知态规则；
- 不修改普通任务中心的全库统计和活动读取能力；
- 只在 React 展示层依据 `qbActiveView` 决定哪些区域渲染。

## 验收

1. 首页摘要、指标和焦点文案统一使用“qB 活跃任务”。
2. `/tasks?qbActive=1` 只显示 qB 当前快照、关联媒体链、刷新和返回入口。
3. qB 专用视图不显示全库四项统计、四个筛选标签、全局摘要、Torra 秒传系统问题或最近活动。
4. 普通 `/tasks` 页面全部原有内容保持不变。
5. 刷新 `/tasks?qbActive=1` 后仍处于专用视图。
6. qB 离线时显示“活跃任务未知”，不得显示 `0`。
7. 两个活跃任务合并为一条媒体链时，同时显示 `2 个`与 `1 条媒体链`。
8. 点击“查看全部任务”后恢复普通任务中心全部内容。
