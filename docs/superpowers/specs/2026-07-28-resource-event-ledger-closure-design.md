# 资源事件台账收口设计

日期：2026-07-28

状态：已实施，待发布验收

方案：A，增量收口现有资源台账；不建立第二套事实表，不重建统一事件账本

## 1. 目标

本轮只解决以下六项问题：

1. 阻止轮询中的 `active`、`waiting` 和 `unknown` 事实持续膨胀永久台账，并清理已经产生的瞬时事件。
2. 让任务的“首次确认可播放”使用历史首次 Emby 命中时间，而不是最近轮询时间。
3. 保留并展示 Symedia 文件级真实失败原因。
4. 让 `archivedDate` 从持久资源事件读取历史归档，并与当前快照按同一文件身份合并去重。
5. 解释追更总数中 Torra 独有、Fluxa 独有、异常和未分类条目的构成。
6. 将日历数量明确表达为“已关联、未关联、合计”。

本轮不修改导航，不引入统一事件总线，不新增第二套订阅或任务台账。

## 2. 事实与事件边界

### 2.1 当前投影

`pipelineFacts` 继续表达当前六阶段事实。`unknown`、`active`、`waiting` 只存在于当前任务投影，不写入 `resource_events`。

进行中的任务必须继续出现在任务中心、追更页和日历当前状态中。清理永久事件不能改变当前投影结果。

### 2.2 永久事件白名单

任务事实只有同时满足以下条件才允许写入永久台账：

- `evidence == verified`；
- `state/status` 属于 `succeeded`、`failed`、`protected`、`not_applicable`。

`not_applicable` 是稳定业务结论，必须保留，重启后仍可从历史台账恢复。

身份迁移、链别名、产物冲突和人工操作使用各自现有写入路径，不受任务事实白名单影响。

### 2.3 失败事件资格

`failed` 不能使用轮询生成的 `observedAt` 作为永久事件身份或发生时间。失败事件只有具备以下两类证据时才入账：

1. 稳定对象身份：结果 ID、文件身份、任务哈希、稳定 `sourceRef` 或等价产物身份；
2. 稳定发生依据：上游真实发生时间或稳定结果/运行 ID。

缺少任一类证据时，失败只保留在当前投影。

永久事件幂等键不得包含 `observedAt`、`freshUntil`、计划重试时间或其他轮询字段。幂等键应由规范链 ID、规范产物或文件身份、阶段、结果状态、稳定结果/运行 ID 和稳定发生时间组成。

同一失败结果的重复轮询必须命中同一幂等键。相同文件在后续新的运行或新的发生时间中再次失败时，必须生成不同幂等键并新增一条事件。

### 2.4 文件单元

永久事件按事实单元写入和查询。父事实可作为当前批次摘要，但不能替代文件单元结果。

混合批次中即使父事实为 `failed`，其中 `verified + succeeded` 的文件单元仍须独立写入成功事件；失败文件也按失败事件资格单独判断。父事实不能阻止成功文件进入归档。

## 3. 一次性迁移

### 3.1 启动顺序

新版本启动顺序固定为：

1. 初始化资源台账结构；
2. 阻断旧版任务快照写入；
3. 创建 SQLite 迁移备份；
4. 执行瞬时事件清理和迁移审计；
5. 启用新版任务事实写入；
6. 注册任务快照及其消费者。

仓储初始化和迁移完成前，任务服务不得获得可写仓储实例。

### 3.2 清理范围

只删除 `resource_events` 中满足以下全部条件的记录：

- `status IN ('active', 'waiting')`；
- `payload_json.kind` 属于 `pipeline_fact`、`pipeline_fact_unit`、`episode_evidence`。

不得删除：

- `succeeded`、`failed`、`protected`、`not_applicable`；
- 身份迁移和链别名记录；
- 产物冲突记录；
- 人工操作记录；
- 非任务事实类审计或调度记录。

清理实现读取并解析候选行的 JSON 类型，不依赖 SQLite JSON 扩展，也不使用宽泛的仅状态删除。

### 3.3 原子性与审计

备份必须在任何删除前成功完成。备份失败时不执行迁移。

删除和迁移审计在同一个 `BEGIN IMMEDIATE` 事务中完成。新增独立的资源台账迁移审计表，不伪造媒体任务或资源链事件。审计至少保存：

- 迁移 ID；
- 执行状态；
- 不含本地路径的备份引用；
- 删除总数；
- 按阶段删除数量；
- 执行时间。

审计写入失败时，删除必须整批回滚。迁移可重复执行；首次成功后再次执行返回删除总数 `0`，且不重复生成审计记录。

迁移结果通过现有任务台账状态以新增可选字段返回，不删除或改型旧字段，也不公开数据库路径。

## 4. 可播放时间

`pipelineOutcome.playableAt` 的唯一优先级为：

```text
firstConfirmedPlayableAt
→ eventAt
→ observedAt
```

仓储在派生结果前先将历史首次 Emby 成功时间投影到 `firstConfirmedPlayableAt`。集级范围事实使用对应集单元的历史首次事件时间。

`completedAt` 继续由 `playableAt` 单向投影。产品文案固定为“首次确认可播放”，不能称为实际首次可播放时间。

## 5. Symedia 失败原因

Symedia 文件单元继续从 `errmsg` 生成真实 `reasonText`。

- 单文件：父事实直接采用该文件的真实原因。
- 多文件：仅汇总与父事实结果相关的文件单元，并按公开后的原因分组计数。
- 混合结果：保留每个文件单元的独立原因和状态，父摘要不覆盖单元事实。
- 无可用原因时才回退到通用失败文案。

所有公开原因继续经过现有脱敏层，内部路径、令牌和私有标识不得进入前端。

## 6. 历史归档

### 6.1 查询来源

`archivedDate` 按 `Asia/Shanghai` 自然日计算 UTC 查询边界，从 `resource_events` 查询 Symedia 文件单元中的 `verified + succeeded` 事件。

归档查询不要求父事实为 `succeeded`，也不读取 `failed`、`protected` 或当前状态推断成功。

### 6.2 统一文件身份

历史事件已经保存不可逆的规范化 `unitKey/sourceRef`。当前快照在参与合并前必须调用与持久化写入完全相同的规范化函数，将原始身份转换为同一种规范身份。

禁止分别对原始值和历史哈希再次散列。文件去重键直接由统一规范身份构成。

### 6.3 合并和所有权

历史事件与当前快照先按规范文件身份合并，再计算计数：

```text
archivedFiles = linkedFiles + unlinkedFiles
```

`linkedTasks` 先解析所有链别名，再按规范链 ID 去重。同一文件在链别名迁移前后只能计入一个任务。

当前 Symedia 离线时，已有历史归档仍可读取。只有历史台账没有可用记录且当前来源也不可用时，才返回来源不可用；不能把离线解释为归档数量为零。

## 7. 数字解释

### 7.1 追更

追更工作台新增互斥构成统计：

- 已关联；
- 仅 Torra；
- 仅 Fluxa；
- 对账异常，包含冲突和远端消失；
- 未分类。

五类之和必须等于追更总数。原有“追更中、已可播放、需要处理、已入库”仍作为业务状态指标，但不再暗示它们可以相加得到总数。

### 7.2 日历

日历接口新增稳定的总量字段，并统一显示：

```text
已关联 N · 未关联 M · 合计 N+M
```

该组数字不随是否打开“未关联”筛选而改变，避免将当前展示数与被排除数重复相加。

## 8. API 兼容性

本轮只增加可选响应字段，不修改现有 URL、HTTP 方法、状态码和已有字段类型。

- 任务台账新增迁移摘要字段；
- 追更统计新增互斥构成字段；
- 日历统计新增已关联、未关联和合计字段。

历史归档在已有持久证据时允许脱离当前 Symedia 在线状态返回成功。这是事实来源修正，不改变无历史且来源不可用时的错误语义。

## 9. 验收

### 9.1 迁移与事件

- 备份失败时删除数为 `0`，数据库不变。
- 审计写入失败时事务回滚，数据库不变。
- 迁移只删除指定任务事实中的 `active/waiting`。
- `succeeded/failed/protected/not_applicable` 和身份、冲突、人工记录全部保留。
- 第二次迁移删除数为 `0`。
- 清理后当前进行中的任务仍正常显示，但不再进入历史时间线。
- 相同失败结果重复轮询不增加事件。
- 同一文件发生新的真实失败时增加一条事件。
- `not_applicable` 在重启后仍可恢复。

### 9.2 时间和原因

- `firstConfirmedPlayableAt` 优先于 `eventAt` 和 `observedAt`。
- 任务卡和详情显示同一个首次确认时间。
- Symedia 单条失败显示真实原因。
- 多条失败按原因分组，不再只显示文件数量。

### 9.3 归档

- 当前快照不再包含旧文件时，历史归档仍存在。
- 混合批次“成功 2、失败 1”归档两个文件。
- 当前快照和历史台账包含同一文件时只计一次。
- 链别名迁移前后的同一文件只产生一个 `linkedTask`。
- Symedia 离线时历史归档仍可读取。
- `archivedFiles = linkedFiles + unlinkedFiles` 始终成立。

### 9.4 统计和回归

- 追更互斥构成之和等于总数。
- 日历显示“已关联、未关联、合计”，三者可严格对账。
- 后端相关单元测试、API 契约测试、TypeScript 类型检查和生产构建全部通过。
