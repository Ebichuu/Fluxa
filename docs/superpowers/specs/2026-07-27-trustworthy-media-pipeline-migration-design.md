# Fluxa 可信影音任务中枢状态与数据边界迁移设计

日期：2026-07-27
状态：已书面复核，批准实施
范围：任务事实模型、派生状态、兼容契约、候选与追更边界、首页、任务中心、追更、日历、控制室、活动记录和旧字段退役

## 1. 决策

本轮立即采用方案 A：契约优先、兼容迁移。方案 B 作为迁移完成后的目标结构；不采用只修前端表达的方案 C。

迁移期间先增加独立事实和统一派生层，旧字段只作为兼容输出。消费者逐步切换后，经过观察期再废弃旧字段，最终只保留新事实模型与派生结果。

本设计解决两个根因：

1. 同一个 `completed` 当前同时表达 Torra 获取目标、Symedia 入库和整条任务完成，导致事实边界混乱。
2. 榜单扫描当前直接写入用户追更台账，导致候选、用户意图和外部执行混在一起。

## 2. 硬约束

以下约束不可在实施中弱化：

1. 事实层分别保存 `torra`、`qb`、`cloud115`、`symedia`、`strm`、`emby`，不得再增加一个混合多个阶段的 `acquisition` 事实。
2. 派生层统一计算 `waiting`、`in_progress`、`protected`、`action_required`、`playable`；缺少必要证据时返回 `evidence_insufficient`。
3. 旧字段只能由新事实和新派生结果单向投影。任何业务流程不得同时写入新旧两套状态。
4. 历史记录缺少明确证据时必须返回 `evidence_insufficient`，不得用 `false`、`0/N`、`未完成` 或相邻阶段成功代替未知事实。
5. Torra `completed` 只表示“获取目标已满足”。
6. Symedia 成功只表示“整理入库完成”。
7. STRM 成功只表示“播放入口已生成”。
8. Emby 当前目标范围的明确证据成功才表示“已可播放”。
9. 只有 `playable` 可以进入最终完成统计。
10. `only_fluxa` 不是垃圾标记。用户手动加入但尚未同步 Torra 的追更必须保留。

## 3. 目标数据模型

### 3.1 目标范围

每条事实必须绑定明确目标范围：

```text
movie
season
episode
file
system-category
```

- 电影可以使用作品级 Emby item 证据。
- 电视剧最终完成必须落到集级 Emby 证据。
- 季级完成只能由明确季集范围内的全部目标集派生；未知总集数时不得生成 `0/N` 或季完成。
- 文件级事实只用于 qB、115、Symedia 和 STRM 的具体文件；不能直接替代集级 Emby 证据。
- 秒传插件没有文件详情时保留 `system-category` 范围，不虚构文件身份。

### 3.2 独立事实

任务快照统一返回 `pipelineFacts`：

```json
{
  "pipelineFacts": {
    "torra": {},
    "qb": {},
    "cloud115": {},
    "symedia": {},
    "strm": {},
    "emby": {}
  }
}
```

每个事实使用同一结构：

```json
{
  "state": "unknown | waiting | active | succeeded | failed | protected | not_applicable",
  "scope": "movie | season | episode | file | system-category",
  "evidence": "verified | inferred | missing",
  "source": "Torra",
  "sourceRef": "公开脱敏引用",
  "observedAt": "2026-07-27T08:00:00Z",
  "freshUntil": "2026-07-27T08:10:00Z",
  "reasonCode": "TORRA_TARGET_SATISFIED",
  "reasonText": "获取目标已满足"
}
```

约束：

- `unknown` 与 `missing` 表示不知道，不等于失败。
- `failed` 必须有当前、明确且可归属的失败证据。
- `protected` 表示策略正常阻止低质量覆盖，不计入失败。
- `inferred` 可以展示为辅助证据，但不能生成 `playable`。
- 每个适配器只写自己负责的事实，不回填上下游阶段。
- 原始凭据、内部路径、Token、Cookie、Passkey 和未经脱敏的外部 ID 不进入公开响应。

### 3.3 六类事实语义

| 事实 | 成功语义 | 不允许推断 |
| --- | --- | --- |
| `torra` | 获取目标已满足 | 不表示 qB 已下载、115 已秒传或媒体已可播放 |
| `qb` | 下载任务已完成 | 不表示文件已进入 115 |
| `cloud115` | 目标文件或明确批次已完成秒传/上传 | 不表示 Symedia 已整理 |
| `symedia` | 文件已完成识别、整理或归档 | 不表示 STRM 已生成或 Emby 已收录 |
| `strm` | 对应播放入口已明确生成 | 不表示 Emby 已扫描并可播放 |
| `emby` | 当前电影或集级目标已被 Emby 明确收录 | 这是唯一可生成 `playable` 的成功事实 |

### 3.4 冲突与新鲜度

- 同一目标可以同时保留多个来源事实，派生器不得覆盖原始事实。
- 同一阶段出现相互矛盾的当前证据时，阶段进入 `evidence_insufficient`，并返回 `EVIDENCE_CONFLICT`。
- 过期证据保留审计值，但不得参与当前派生状态。
- 下游成功不能补写上游事实；只能在用户说明中表达“目标已达到，上游证据未关联”。

## 4. 统一派生层

### 4.1 派生响应

所有页面使用同一个 `pipelineOutcome`，不再分别解释 `state`、`chainState`、`fulfillmentState` 和 `inLibrary`：

```json
{
  "pipelineOutcome": {
    "state": "playable",
    "label": "已可播放",
    "reasonCode": "EMBY_EPISODE_VERIFIED",
    "reasonText": "Emby 已收录当前目标集",
    "currentStage": "emby",
    "primaryAction": null
  }
}
```

### 4.2 判定顺序

派生器按以下顺序处理同一目标：

1. 当前目标存在有效、明确的 Emby 成功事实时为 `playable`。上游缺失只进入诊断，不阻止最终目标成立。
2. 未达到 `playable` 且存在明确、未恢复的当前失败时为 `action_required`。
3. 存在活动任务或有效自动恢复计划时为 `in_progress`。秒传未来重试必须计入处理中。
4. 最新有效结果是质量保护且没有活动任务或真实失败时为 `protected`。
5. 已知用户意图有效，当前只是等待播出、等待来源或等待正常下一阶段时为 `waiting`。
6. 身份、范围或必要事实缺失，无法可靠落入以上状态时为 `evidence_insufficient`。

不得根据布尔值默认值、数值零或页面是否有记录推断状态。

### 4.3 统计口径

- `completedCount` 只统计 `pipelineOutcome.state=playable`。
- `actionRequiredCount` 只统计用户可处理的明确失败。
- `inProgressCount` 包含媒体任务和正在自动恢复的系统任务。
- 秒传只有分类级失败数时，可把明确失败数计入处理中，但不得展示不存在的文件名。
- RSS 来源异常、服务连接异常和媒体任务异常分别统计，不合并成同一个红色数字。
- 首页、导航角标、任务中心标签和深链必须消费同一份派生统计。

## 5. 兼容契约与单向投影

### 5.1 兼容原则

第一阶段在现有 v2 响应中增加可选的 `pipelineFacts`、`pipelineOutcome` 和新统计，不删除旧字段，不要求旧消费者立即修改。

兼容适配器是旧字段的唯一来源：

```text
来源适配器 -> pipelineFacts -> pipelineOutcome -> legacy projection
```

禁止以下路径：

```text
旧字段 -> pipelineFacts
业务流程同时写 pipelineFacts 和旧字段
前端根据旧字段二次推导 pipelineOutcome
```

### 5.2 旧语义处理

- 迁移初期，旧字段可以保持原有兼容语义，但必须由新事实投影，并标记为 deprecated。
- 新页面不得再读取旧字段决定状态。
- 最终完成统计立即切换到 `pipelineOutcome`，不能继续使用兼容 `completed`。
- 旧字段不得在同一 API 版本内悄然改变类型；删除或重命名进入后续契约版本。
- 每个兼容字段在 `docs/API_CONTRACT.md` 登记替代字段和退役条件。

### 5.3 影子比较

消费者切换期间同时计算旧投影与新结果，只记录脱敏差异摘要：

- 旧完成、新不可播放；
- 旧 0/N、新证据不足；
- 旧 Torra 运行中、新获取目标已满足；
- 旧需要处理、新自动恢复中；
- 新旧完全一致。

影子比较只用于观察，不反向修改事实。

## 6. 候选与用户追更边界

### 6.1 三层模型

数据流固定为：

```text
榜单与发现来源 -> discover_candidates -> 用户明确加入 -> subscription intent -> Torra/其他 provider
```

- 榜单刷新只能新增或更新候选。
- 候选不得出现在追更列表、任务中心和默认日历。
- 只有用户明确加入，或未来单独设计并明确开启的自动规则，才能建立追更意图。
- 建立追更意图后才允许调用 Torra 或其他外部 provider。
- 自动来源扫描不得直接写追更台账或触发外部获取。

### 6.2 候选记录

候选至少保存：公开候选 ID、媒体类型、TMDB 身份、标题、年份、来源、首次/最近观察时间、展示摘要和过期状态。

候选原始响应不得直接作为公开 DTO，也不得保存外部凭据。

### 6.3 历史污染清理

历史行按证据分为四类：

1. 明确人工加入：保留为追更，包括 `only_fluxa`。
2. 已关联 Torra 或已有下游任务事实：保留追更并进入新事实模型。
3. 明确自动榜单来源，且没有人工动作、Torra 关联或下游事实：迁入候选池。
4. 来源不明或证据冲突：保留并标记 `migration_review`，不得自动删除。

清理必须使用“预览 -> 备份 -> 明确确认 -> 条件迁移 -> 复查 -> 留痕”。不得按 `only_fluxa` 批量删除。

## 7. 页面职责

### 7.1 任务中心与首页

- 第一批切换到 `pipelineOutcome` 和统一统计。
- 任务中心默认页签顺序：有异常时打开“需要处理”；否则有活动任务时打开“处理中”；其余打开“已可播放”或“无需处理”。
- 首页分开显示“媒体需要处理”和“辅助能力提醒”。
- 顶部媒体异常入口进入任务中心对应筛选和任务；控制室只作为管理入口。
- 自动重试中的秒传失败进入处理中，不同时显示为终态失败。
- 空闲 `0 B/s` 不作为首屏主结论。

### 7.2 追更与日历

- 追更卡片分别显示“已在 Torra”“Torra 获取中”“获取目标已满足”“仅 Fluxa 保存”“对账异常”。
- Torra `completed` 不再显示为最终完成。
- 没有集级事实时显示“集数进度未确认”，不显示 `0/N`。
- 日历默认只包含已确认用户意图、已关联 Torra 的有效追更和明确季集范围。
- `migration_review` 和状态未关联记录进入独立筛选，不进入默认月视图。
- 日历“已可播放”只来自集级 Emby 事实。

### 7.3 控制室与 Symedia

- Symedia 历史接口可读只能表达为“历史接口可读”。
- 归档监控、CloudDrive、Webhook、STRM、调度和文件观察分别接入；未接入时为 `unknown`。
- “全部服务证据可用”必须要求所有声明能力都有当前证据，不能只看一个历史接口。
- 洗版摘要区分成功替换、低分保护、取消覆盖、真实失败和最近一次目标。

### 7.4 发现、筛选与活动记录

- 发现卡片保留海报、标题、年份、评分、两行摘要和加入追更；完整剧情进入详情。
- 追更默认只显示搜索、追更中、需要处理、已可播放和仅缺集；年份、更新时间和对账状态进入更多筛选。
- 筛选和深链使用新派生状态；旧 URL 在迁移期映射到新状态。
- 活动重点视图按一次业务运行聚合，显示总数、成功、跳过和失败摘要；单项失败进入展开内容。
- 原始活动记录继续保留，但不作为默认视图。

## 8. 外部证据接入

### 8.1 Torra 秒传

- 读取 `recent_runs.result.failure_details`，存在真实详情时才设置文件级证据可用。
- 本次运行没有详情时显示“本次记录没有文件级详情”，不得写成永久能力限制。
- `nextRunAt`、活动运行和重试策略共同决定自动恢复状态。
- 文件详情必须脱敏，不能公开路径、凭据和内部任务 ID。

### 8.2 STRM 与 Emby

- Symedia 成功记录中的目标路径只能作为 STRM 候选，不直接等于 STRM 成功。
- STRM 成功必须来自明确的生成结果、服务状态或可验证文件事实。
- Emby 作品级命中只证明作品存在；电视剧必须有当前集级映射才能生成 `playable`。
- 无法唯一绑定集级目标时保持 `evidence_insufficient`。

## 9. 迁移波次

### P0：正确性与数据边界

P0 拆为可独立提交、独立回滚和独立验收的小阶段：

1. 新增六类事实 DTO、持久字段、统一派生器和兼容投影，不修改旧消费者。
2. 接入 Torra、qB、115、Symedia、STRM、Emby 事实适配器；先消费当前已有的明确证据，缺少来源的阶段保持 `unknown`，并禁止旧状态直接写入。
3. 任务中心与首页切换新派生状态，统一完成、处理中、异常和深链统计。
4. 追更与日历切换新语义，区分 Torra 目标满足和 Emby 已可播放。
5. 建立候选池，停止榜单写追更，并提供历史污染迁移预览与安全执行。

每一阶段必须先完成契约测试和回归，再进入下一阶段。

### P1：证据深度与操作闭环

1. 扩展接入 Symedia 服务组与 STRM 专用来源，并补齐洗版结果摘要。
2. 读取 Torra 文件级失败详情并改进秒传恢复展示。
3. 为明确失败提供任务深链、打开原工具或安全预览/确认动作。
4. 完成历史污染数据的受控清理和迁移复查。

### P2：信息密度与长期使用

1. 精简发现卡片、追更筛选和日历默认视图。
2. 活动记录改为业务运行摘要，保留可展开明细。
3. 移除空闲速度等低价值首屏信息。
4. 迁移筛选、URL 深链和分享上下文，保证前进、返回和刷新连续。

### 退出阶段：达到方案 B

所有消费者完成迁移后进入至少 7 个连续自然日的观察期，并至少覆盖一次真实电影闭环和一次真实剧集集级闭环。满足以下条件后才能删除旧字段：

- 运行时没有旧字段写入；
- 前端和首页统计不读取旧状态；
- 新旧影子差异均已解释或修复；
- 历史迁移预览没有未处理的高风险冲突；
- API 文档和部署回滚说明已更新；
- 完整测试与实机只读核对通过。

旧字段删除进入新的契约版本，不在兼容响应中静默删除。

## 10. 错误处理与安全边界

- 来源不可用时保留上次事实并标记过期，不把连接失败写成业务失败。
- 任何写外部系统的动作继续使用预览、确认、幂等、冷却和审计。
- 候选迁移和历史清理默认只读预览，不因标题相似自动合并。
- 用户说明与技术说明分离；公开响应不泄露内部路径和凭据。
- 迁移失败必须保持事务原子性，并保留迁移前备份。
- 回滚只切换消费者和兼容投影，不反向根据旧字段重建新事实。

## 11. 测试与验收

### 11.1 状态真值表

必须覆盖：

- Torra 完成、下游未知 -> 获取目标已满足，不是最终完成；
- Symedia 成功、STRM/Emby 未知 -> 入库完成，整体为 `evidence_insufficient`；
- STRM 成功、Emby 未知 -> 播放入口已生成，整体为 `evidence_insufficient`；
- Emby 当前集明确命中 -> `playable`；
- Emby 作品级命中但集级未知 -> 不可生成剧集 `playable`；
- 计划重试有效 -> `in_progress`，不进入需要处理；
- 质量低分保护 -> `protected`；
- 明确失败且无恢复计划 -> `action_required`；
- 历史字段只有 `false` 或 `0/N` -> `evidence_insufficient`。

### 11.2 数据边界

- 榜单刷新只更新候选表，追更数量不变，也不触发外部写操作。
- 用户明确加入后才建立追更意图。
- 人工 `only_fluxa` 保留；明确自动污染行可预览迁入候选池。
- 冲突行不自动删除或改绑。

### 11.3 契约与兼容

- 新字段为结构化 DTO，旧字段全部来自兼容投影。
- 旧客户端在第一阶段保持可用。
- 新客户端不读取旧字段派生状态。
- 列表、详情、摘要、搜索和日历对同一目标返回一致结果。

### 11.4 页面与实机

- 首页、导航角标和任务中心数量一致。
- 有异常时任务中心首屏直接展示异常任务。
- 追更不再用“Torra 运行中”表达仅存在。
- 默认日历不显示候选和未确认污染记录。
- 控制室准确说明 Symedia 已接入和未接入能力。
- 320、390、768、1440 视口、深浅主题、键盘和 URL 回归通过。
- 实机验证只在用户明确批准的窗口执行，不因本设计自动开启调度或外部写入。

## 12. 非目标

- 不重写 Torra、qB、115、Symedia、STRM 或 Emby 的业务引擎。
- 不建立第二套下载器、媒体库或质量评分器。
- 不用标题模糊匹配制造集级完成证据。
- 不在候选分离阶段顺带重做全站视觉语言。
- 不在兼容期一次性删除旧 API 字段。
