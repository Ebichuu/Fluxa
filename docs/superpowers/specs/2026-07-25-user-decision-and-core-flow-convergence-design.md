## 1. 决策与目标

本轮不更换 Fluxa 现有工业感，也不继续做零散字号补丁。目标是让普通用户不理解 Torra、qB、115、Symedia、STRM 和 Emby 的职责，也能完成三条闭环：

1. 搜索作品 → 添加追更 → 明确确认已生效；
2. 首页发现异常 → 定位具体作品和阶段 → 执行一个主操作 → 明确确认已恢复；
3. 搜索任意作品 → 在一页看完追更、下载、115、入库、Emby 和播放状态。

本设计采用“后端统一用户决策字段 + 前端按业务结果展示”的方案。技术状态继续保留，用于兼容、诊断和测试，但不再作为普通页面的主要信息架构。

本设计同时取代以下旧结论：

- 11px 只作为标签、时间和胶囊的下限，不再作为大面积正文目标；
- “正常保护”不再建议主动清理文件，统一表达为“已保留更高质量版本，无需处理”；
- 普通任务筛选不再直接展示“卡住、疑似阻塞、证据不足、正常保护”等内部分类；
- 普通追更和 RSS 页面不再直接展示对账、匹配器、身份回填和原始证据字段；
- 除首页外，管理页面不再使用高占比 Hero。

## 3. 四类日常任务状态

新增稳定字段 `userState`，普通页面只展示四类：

| userState | 中文 | 判定规则 |
| --- | --- | --- |
| `action_required` | 需要处理 | 存在已确认失败、真实阻塞，或有明确且安全的用户动作 |
| `in_progress` | 处理中 | 下载、分析、同步、等待已安排重试或其他正常执行过程 |
| `completed` | 已完成 | 目标的最终业务阶段已完成，有入库或最终可看证据 |
| `no_action` | 无需处理 | 正常保护、只读历史、身份待整理、诊断性证据不足，且没有真实执行失败 |

现有 `healthState`、`executionState`、`identityState` 和阶段证据继续返回，但只进入“高级诊断”。

具体规则：

- `executionState=confirmed_failed/action_required` 优先进入“需要处理”；
- 活跃 qB、Torra 分析、调度等待和计划重试进入“处理中”；
- 入库阶段完成进入“已完成”；Emby 已识别只作为完成结果的附加证据，不伪造具体单集状态；
- `protected` 进入“无需处理”，文案为“已保留更高质量版本，无需处理”；
- 单纯 `unidentified/conflict/evidence_insufficient/suspected_blocked` 不进入红色状态，只在高级诊断中提示；
- 身份问题不得覆盖真实执行失败；真实执行失败也不得因为身份未关联而降级。

任务中心默认结构为：

- 处理中；
- 需要处理；
- 今日完成；
- 无需处理作为显式筛选入口。

“已完成”筛选可查看全部历史，默认页中的完成区只显示北京时间当天完成的目标。

## 4. 统一任务结果与唯一主操作

任务摘要新增：

```json
{
  "userState": "completed",
  "resultText": "已下载 13 个 · 已入库 · Emby 已识别",
  "completedAt": "2026-07-25T06:30:00Z",
  "primaryAction": {
    "kind": "none",
    "label": "",
    "available": false,
    "reason": "任务已完成"
  }
}
```

`resultText` 只能使用已验证事实：

- 有 qB 完成数量才显示“已下载 N 个”；
- 115 阶段只有逐文件或下游强证据才能显示“已进入 115”；
- Symedia 入库完成才显示“已入库”；
- Emby 有作品级或季集级证据才显示“Emby 已识别/可看”；
- 证据不足时省略该段，不以“可能、应该”补齐句子。

每张异常卡只有一个主操作。`primaryAction.kind` 使用固定枚举，例如：

- `reidentify`；
- `resume_download`；
- `pause_download`；
- `retry_stage`；
- `refresh_source`；
- `open_qb`；
- `open_torra`；
- `view_subscription`；
- `none`。

“查看详情”是低权重导航，不与主操作竞争；“打开原工具、复制信息、技术详情”进入“更多”或高级诊断。前端不得根据文案猜动作资格。

## 5. 首页决策规则

首页主结论只由真实可操作状态决定，优先级为：

1. `actionRequired > 0`：`有 N 项需要处理`；
2. 当前有活动任务：`正在处理 N 个任务`；
3. 今日有完成结果：`今日媒体处理正常`；
4. 无活动和异常：`影音中心运行正常`；
5. 首页接口本身读取失败：`暂时无法确认影音中心状态`。

身份未关联、匹配冲突、Torra 分类级秒传记录、RSS 匹配器未运行等诊断信息不得将首页降为黄色。它们进入中性的 `diagnostics`。

首页核心统计固定为明确单位：

- 归档文件 248；
- 完成作品/季 3；
- qB 下载任务 1；
- 需要处理 0。

数字与单位必须分开渲染。统计卡可以点击：

- 下载任务 → 任务中心“处理中”；
- 需要处理 → 任务中心“需要处理”；
- 完成作品/季 → 任务中心“今日完成”；
- 归档文件 → 今日完成视图，并明确提示该统计按文件计数。

首页响应新增：

```json
{
  "issueTotal": 0,
  "issues": [],
  "diagnostics": [
    {
      "code": "TASK_IDENTITY_PENDING",
      "count": 131,
      "label": "131 条记录尚未完成身份整理",
      "href": "/tasks?advanced=1&identityState=unidentified&identityState=conflict"
    }
  ]
}
```

接口可以限制首页问题预览数量，但必须返回 `issueTotal`。前端展示“另外还有 N 项”，不能通过 `slice(0, 4)` 隐藏总量。

## 6. API 契约与兼容

### 6.1 任务接口

保留现有 `/api/v2/tasks/chains` 和所有旧字段，新增可选字段：

- `userState`；
- `resultText`；
- `completedAt`；
- `primaryAction`；
- `userCounts`。

新增查询参数：

- `userState=action_required|in_progress|completed|no_action`；
- `completedDate=YYYY-MM-DD`，按 `Asia/Shanghai` 解释；
- `identityState` 支持重复参数，旧的单值请求继续有效。

无效枚举返回 `400` 和稳定机器码。新增响应字段为非破坏性变更。

### 6.2 RSS 定向匹配与下载

新增：

```text
POST /api/v2/rss-matches
POST /api/v2/rss-matches/{matchId}/torra-rewashes
```

创建匹配请求：

```json
{
  "rssItemId": "...",
  "subscriptionId": "...",
  "unitId": "..."
}
```

服务端必须重新验证媒体类型、TMDB、季集范围、观察单元和 Torra 订阅归属。匹配已存在时返回 `200`，新建时返回 `201 + Location`；不得调用全局 matcher 代替单条匹配。

分析继续使用：

```text
POST /api/v2/rss-matches/{matchId}/torra-rewash-analyses
```

下载请求必须包含 `confirm=true`、分析动作 ID 和幂等键。服务端验证分析动作属于同一个 RSS 匹配、订阅和观察单元。

分析结果只公开脱敏候选摘要，例如当前评分、候选评分、质量标签和大小；不公开候选 ID、下载 URL、Cookie、Passkey 或上游原始响应。

### 6.3 发现来源状态

发现搜索和资源搜索响应新增：

```json
{
  "sourceStatuses": [
    {"key": "tmdb", "label": "TMDB", "status": "available", "count": 0, "message": "已搜索，未找到结果"},
    {"key": "rss-main", "label": "主站 RSS", "status": "unavailable", "count": 0, "message": "最近收集失败"}
  ]
}
```

`status` 只允许 `available/unavailable/disabled/not_configured`。错误说明必须脱敏。

### 6.4 日历完整索引

月摘要继续只返回每天前三条 `preview` 用于画面展示，同时新增完整轻量 `searchIndex`：

```json
{
  "date": "2026-07-25",
  "key": "...",
  "title": "作品名",
  "episodeLabel": "S01E04",
  "mediaType": "tv",
  "status": "upcoming"
}
```

月历搜索和状态筛选必须基于完整 `searchIndex`，不能再搜索 `day.preview`。日期详情仍按需读取完整记录。

### 6.5 全局搜索与作品总览

新增：

```text
GET /api/v2/search?q={query}&limit={limit}
GET /api/v2/media/{mediaKey}
```

全局搜索优先聚合 Fluxa 本地追更、任务、日历、RSS 身份和 Emby 索引；需要补充远端媒体时再查询 TMDB。相同 `mediaKey` 只返回一条结果。

作品总览响应统一包含：

- 追更状态与 Torra 生效状态；
- 最近检查时间；
- 已下载到第几集；
- 已入库到第几集；
- Emby 是否可看；
- 当前唯一主操作；
- 任务、日历、追更和播放深链。

## 7. 三条核心流程

### 7.1 搜索作品 → 添加追更 → 确认生效

1. 用户从顶部全局搜索或发现页找到作品；
2. 点击“添加追更”；
3. Fluxa 显示动作状态：已收到 → 已保存追更意图 → 正在同步 Torra → Torra 已建立 → 已安排最近检查；
4. 只有拿到 Torra 远端 ID 或明确只读生效证据后，才显示“追更已生效”；
5. 如果推送开关关闭或路径未配置，明确显示阻塞原因和一个主操作；
6. 操作记录可从作品总览和活动记录回看。

### 7.2 首页异常 → 处理动作 → 确认恢复

1. 首页问题卡必须带稳定 `issueId/chainId/stage`；
2. 点击后进入具体任务并展开问题阶段；
3. 卡片只突出一个主操作；
4. 写操作遵循预览、确认、幂等执行；
5. 前端根据 `202 Location` 轮询动作状态，显示已收到、执行中、成功或失败；
6. 动作成功后自动刷新任务证据；
7. 只有原问题证据消失或被新成功证据覆盖时，显示“已恢复”；
8. 用户无需手工刷新或重新寻找任务。

### 7.3 搜索任意作品 → 一页看完全部状态

顶部全局搜索结果示例：

> 《雀骨》
> 追更中 · 已下载 13 集 · 已入库 · Emby 可看

主操作按状态决定，最多展示三个入口：

- 查看作品总览；
- 查看任务/日历；
- 打开播放。

作品总览是隐藏路由，不进入主导航。推荐路径为 `/media/{mediaType}/{tmdbId}`，季号使用查询参数保存。页面展示追更生命周期、当前任务结果、最近日历、入库和播放状态；技术证据放入折叠诊断。

## 8. URL、返回与时间连续性

以下状态必须写入地址参数：

| 页面 | 参数 |
| --- | --- |
| 任务 | `userState`、`completedDate`、`advanced`、`identityState`、`chainId`、`targetKey` |
| 日历 | `year`、`month`、`view`、`type`、`status`、`q`、`date` |
| 发现 | `source`、筛选条件、`q`、页码 |
| 追更 | 类型、状态、年份、搜索词、订阅 ID、季号 |
| RSS | `q`、来源、时间范围、页码；诊断筛选只在 `advanced=1` 时保存 |
| 作品总览 | 媒体类型、TMDB ID、季号 |

显式切换月份、打开日期、打开作品和选择任务使用 `pushState`；输入中搜索和同页筛选使用 `replaceState`，避免污染返回历史。

应用需要保存每个页面的滚动位置。浏览器返回时先恢复查询参数和展开项，再恢复滚动位置；直接打开链接时不得使用旧会话滚动位置。

统一 `RelativeTime` 组件：

- 默认显示相对时间；
- `title` 和可访问标签显示完整北京时间；
- 点击或键盘激活后切换为完整北京时间，解决手机无 hover；
- 输出使用 `timeZone=Asia/Shanghai` 和 `tabular-nums`。

## 9. UI 收敛规则

### 9.1 字体

- 页面正文、原因说明：13–14px；
- 卡片数据、次要信息：12px；
- 胶囊、时间、字段标签：11px；
- 可点击标题：至少 14px；
- 长文不得通过压到 11px 解决布局问题。

### 9.2 三层视觉结构

只保留：

1. 页面背景；
2. 主要功能区；
3. 可点击项目或异常项目。

普通说明通过留白、标题和分隔线区分，不再使用“面板 → 卡片 → 内部卡片 → 状态框”的嵌套结构。主要功能区可以有一个边框；内部静态信息默认无独立背景和圆角。

### 9.3 状态颜色

- 红色只用于真实异常；
- 蓝色用于处理中；
- 正常保护使用低饱和蓝灰；
- 普通正常使用中性色，只保留一个小绿点；
- 页面和大卡片背景不随状态整体变色；
- 发光只允许在线小状态点，异常不使用大面积光晕。

### 9.4 按钮

每个功能区：

- 一个主按钮；
- 最多两个次按钮；
- 其他动作进入“更多”。

统一四种基础组件：主按钮、次按钮、文字按钮、图标按钮。现有命令按钮只保留在真正的批量管理动作中，不与普通业务按钮混用。

### 9.5 页头与数字

首页保留完整 Hero。任务、日历、追更、发现、控制室、设置和 RSS 改为紧凑标题栏，例如：

> 任务中心
> 0 项需要处理 · 1 个下载中　[刷新]

数字统一使用 `font-variant-numeric: tabular-nums`，统计值右对齐，数字和单位分开。加载态使用固定宽度骨架，避免刷新抖动。

### 9.6 移动端

- 任务和日历只显示当前筛选摘要与“筛选”按钮；
- 点击后打开底部筛选面板，不再堆多排横向胶囊；
- 手机月历仍保留七列，每格只显示一张海报；海报铺满下半区，数量为右上角角标，状态为底部细色条；
- RSS 列表改卡片，只显示标题、来源、发布时间和业务状态，技术字段展开后查看；
- 查看详情在桌面使用右侧抽屉，手机使用底部全屏面板；
- 危险确认继续使用居中确认框；
- 技术诊断使用折叠区域。

### 9.7 海报与主题

海报状态统一为：加载骨架、暗色渐变失败态、作品首字或类型图标。不得使用纯白占位。

新增统一语义变量：

- 页面/主要功能区/交互项表面；
- 主文字/次文字/标签文字；
- 静默边框/交互边框；
- 异常/处理中/正常保护/正常点；
- hover/disabled/focus/overlay。

深浅主题只在根级定义变量值。页面样式禁止为浅色主题重复写整套颜色覆盖。

## 10. RSS、追更与 Torra 证据

### 10.1 RSS 普通视图

普通页面只回答：

> RSS 正常收集，但暂未匹配到追更作品。

默认显示来源是否正常、最近收集、搜索结果和可用于追更的业务状态。“身份回填、扫描、冲突、未变化、匹配器”及维护按钮进入高级诊断。

### 10.2 追更普通视图

每部作品统一展示生命周期：

`已添加追更 → 已同步 Torra → 最近检查 → 已获取到第几集 → 已入库到第几集 → 是否已完结`

Fluxa/Torra 对账、qB、115、原始健康状态、范围证据和内部 ID 进入高级区域。

### 10.3 Torra 秒传证据

2026-07-25 实机只读审计确认：

- `GET /api/v1/plugins/secupload_115` 返回最近 20 条分类运行；
- 每条有运行 ID、任务、分类、状态、时间、消息和分类级计数；
- `result` 与 `progress` 字段在当前 20 条历史中均为空对象；
- 没有文件名、完整路径、qB Hash、115 文件 ID 或单文件状态。

因此当前可以显示：

> Torra 最近批次成功 14 个，无法绑定到当前具体文件。

不得显示：

> 该任务已完成 115 秒传。

只有后续 Torra 返回文件名、文件 Hash、qB Hash、明确文件任务 ID 或 115 文件 ID，并能唯一绑定 `artifactKey` 时，才将 `perFileEvidence=true` 并把单个任务的 115 阶段标记为完成。

## 11. 操作反馈与异常处理队列

所有耗时操作统一状态：

`accepted → queued/running → succeeded/failed/cancelled → evidence_refreshed → resolved`

前端不得只提示“已提交”。动作面板必须持续显示当前阶段、最后更新时间、最终结果和是否仍需处理。

异常处理队列使用稳定 `issueKey`，由 `chainId + stage + reasonCode + targetKey` 组成。持久状态：

- `new`：新问题；
- `acknowledged`：已知问题；
- `snoozed`：稍后提醒；
- `ignored_once`：忽略本次证据，证据版本变化后重新出现；
- `watching`：持续观察自动恢复；
- `resolved`：新证据确认恢复。

真实异常的技术状态不因用户标记而改变；处理队列只改变首页呈现和提醒策略。自动恢复后保留解决时间和最后成功证据。

## 12. 设置、我的关注、Telegram 与首次使用

### 设置影响说明

每个开关和连接字段必须提供：

- 开启后会发生什么；
- 关闭后会停止什么；
- 是否影响 Torra 现有订阅；
- 是否需要重启；
- 立即生效、下次调度生效或重启生效。

保存后返回“连接验证成功”“配置已保存但服务不可用”或“需要重启”，不能只显示“保存成功”。

### 我的关注

首页支持固定以下六项：

- 当前下载；
- 秒传失败；
- 下载完成但未入库；
- 今日入库；
- 追更缺集；
- 真实异常。

默认固定这六项，允许调整顺序和隐藏；它们只改变首页呈现，不改变任务事实。

### Telegram 连续体验

新通知携带 Fluxa 深链，直接定位作品、季集、任务和失败阶段。通知发送后保存 `chatId/messageId/issueKey` 的脱敏引用。

问题恢复时优先编辑原机器人消息为“已恢复”；若原消息不可编辑或旧通知没有 message ID，则发送一条关联恢复通知。任何通知链接不得包含 Token、Cookie、Passkey 或内部凭据。

### 首次使用

首次进入管理工作台显示三句话：

1. Fluxa 负责帮你追更和查看进度；
2. 资源会经过下载、网盘和入库，最后出现在 Emby；
3. 平时只处理首页红色项目，蓝色和灰色项目可以等待。

引导可关闭，关闭状态保存在用户偏好中，不阻塞正常使用。

## 13. 验收标准

### 状态与首页

1. 实机 `actionRequired=0`、下载任务 1、今日归档 248、身份待整理 131 时，首页不显示黄色故障。
2. 首页显示“归档文件 248、完成作品/季 N、qB 下载任务 1、需要处理 0”。
3. 身份诊断点击后进入带高级身份筛选的任务链接。
4. 首页问题超过四项时显示完整总数和“另外还有 N 项”。

### 任务与动作

5. 普通任务界面只显示四类状态。
6. 每张任务卡有一句话结果；异常卡只有一个主操作。
7. 正常保护显示“已保留更高质量版本，无需处理”，不建议清理。
8. 动作从提交到最终证据刷新全程可见，成功后自动显示已恢复。

### 发现、日历、RSS 与追更

9. 无结果时列出搜索来源及不可用来源。
10. 当目标位于某天第 4 条以后，月历搜索仍可定位该日期。
11. RSS 普通页不出现身份回填、扫描、未变化和匹配器术语。
12. 追更普通卡不直接展示 Fluxa/Torra 对账、qB 和 115 技术字段。
13. RSS 搜索结果可以完成安全匹配、分析、候选摘要和确认下载。

### 连续性与 UI

14. 任务、日历、发现、追更和 RSS 关键筛选可复制链接并恢复。
15. 浏览器返回恢复原筛选、展开项和滚动位置。
16. 相对时间可查看完整北京时间。
17. 普通正文不低于 13px，可点击标题不低于 14px。
18. 页面只保留三层视觉结构，普通正常项没有大面积状态色。
19. 390px 下筛选通过底部面板完成，月历每格只显示一张海报且无页面级横向溢出。
20. 深浅主题均只依赖语义变量，不出现白底白字。

### 三条核心流程

21. 搜索作品添加追更后，可以看到从意图保存到 Torra 生效的连续状态。
22. 首页异常可以定位、处理并确认恢复。
23. 全局搜索结果可以进入作品总览，一页查看追更、下载、入库、Emby 和播放状态。

### 安全与发布

24. 所有新增写接口有权限、幂等、确认和归属校验。
25. 候选、通知和错误响应不泄露下载 URL、Token、Cookie、Passkey、路径或内部 ID。
26. 前后端测试、API 契约测试、类型检查、生产构建、移动端与深浅主题回归全部通过后才更新镜像 `latest`。

## 14. 非目标

- 不替代 Torra、qB、Symedia 或 Emby 的全部高级管理能力；
- 不把缺少逐文件证据的 Torra 分类运行推断成单文件完成；
- 不在本轮重做影视大厅视觉；
- 不开放自动批量下载或无确认的远端写入；
- 不为了减少页面高度重新降低字号；
- 不在普通页面恢复原始路径、Hash、内部 ID 和上游错误原文。
