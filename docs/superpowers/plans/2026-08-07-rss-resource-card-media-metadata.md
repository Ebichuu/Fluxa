# Fluxa RSS 资源卡片媒体身份与使用体验更新计划

日期：2026-08-07
状态：已实施，待发布验收
实施边界：只修改 Fluxa；不修改 Torra、qBittorrent、Symedia、p115client 或 TMDB 远端数据

## 1. 目标

资源中心优先回答“这是什么作品、覆盖哪些集、是否与我的追更有关、多个版本如何比较”，同时保留原始种子名和技术信息用于核对。

本阶段完成以下闭环：

1. 为已有可靠身份的 RSS 资源补充中文名、年份和海报。
2. 中文名展示后可以用同一中文名搜索回对应资源。
3. 明确多集范围与真正的范围待确认分开表达。
4. 手机端无需展开即可比较季集、大小和核心版本信息。
5. 未进入追更或评分链路的普通资源使用中性状态，不制造待办感。
6. 搜索提供明确的提交按钮，并保持回车提交能力。

## 2. 不可突破的边界

1. 媒体身份只来自本地已有、可核验的数据，不根据种子标题猜测 TMDB 身份。
2. 卡片列表请求不得现场调用 TMDB，也不得因外部服务超时阻塞资源列表。
3. 身份来源冲突时不选择任意一项，不返回可能错误的中文名或海报。
4. 不暴露订阅原始 payload、Token、Cookie、Passkey、RSS 下载地址或内部服务地址。
5. 不修改 RSS 原始条目、Torra 订阅、候选评分、下载状态或外部任务。
6. 新增字段保持可选，旧前端和旧缓存仍能读取原有 API。
7. 搜索合并保持分页、总数和排序可对账，不能先分页再追加中文命中。

## 3. 只读媒体元数据解析层

新增统一的只读媒体元数据解析器，批量加载本地证据，并按以下优先级确定资源身份：

1. 当前 RSS 匹配已经绑定的订阅身份。
2. 精确命中的 `mediaType + tmdbId + season` 订阅身份。
3. 精确命中的发现候选身份。
4. 现有 TMDB 本地缓存。

每层都必须满足：

- 媒体类型和 TMDB ID 唯一一致；
- 剧集季号与目标资源一致；
- 海报与标题属于同一个规范身份；
- 多个同优先级来源冲突时返回无元数据，而不是降级猜测；
- 批量查询避免逐卡片 N+1 读取。

解析结果只包含可选的 `mediaTitle`、`mediaYear` 和 `posterUrl`。内部可使用规范媒体键参与搜索，但不得把敏感来源信息返回前端。

## 4. 资源 API 与中文搜索

资源列表、详情和搜索使用同一套身份解析结果。冲突、弱匹配或没有可靠身份时省略三个可选字段；无海报时不返回空字符串或失效占位地址。

搜索流程为：

1. 使用现有逻辑匹配原始种子标题及已有字段。
2. 在本地媒体标题中匹配中文名。
3. 合并原始标题和媒体标题命中并去重。
4. 在完整结果集合上排序、计数和分页。

必须保证卡片显示的 `mediaTitle` 可以搜索回该资源，中文与原始标题同时命中时只返回一条，`total` 与翻页结果严格可对账。

## 5. 范围分类与状态文案

资源范围分为：

- `explicit_episode`：开始集与结束集相同；
- `explicit_multi_episode`：同一季且开始集、结束集均明确，例如 `S01E01-E04`；
- `season_pack`：明确季包，但没有可执行的单集范围；
- `scope_pending`：范围证据缺失、跨季、倒序或解析冲突。

明确多集不再显示“范围待确认”；分类只影响表达，不改变底层匹配、评分和执行安全门禁。

状态文案固定为：普通未匹配资源显示“未关联”，已进入匹配但尚未评分显示“等待评分”，活动动作显示“分析中”。

## 6. 卡片与响应式布局

桌面端使用稳定网格组织海报、发布名、媒体标题、技术信息、状态和动作。海报尺寸为 `56 x 84px`；手机端为 `48 x 72px`。

原始发布名保留为主要技术标题，下面显示媒体标题和可选年份。无海报或海报失败时恢复紧凑无图布局，不显示破图、纯白卡片或装饰占位；同一失效地址在当前应用生命周期内不重复请求。

手机端默认保留季集范围、大小和前三个核心版本标签。长发布名允许换行，不能挤压状态和主要动作。搜索框保留回车提交，并新增有可访问名称的搜索按钮。

## 8. 验收场景

1. RSS 匹配订阅身份优先于其他来源。
2. 精确订阅、发现候选和 TMDB 本地缓存按顺序降级。
3. 同优先级身份冲突时不返回标题和海报。
4. 无海报时省略字段并使用紧凑布局。
5. 中文标题能搜索回对应资源。
6. 中文与原始标题同时命中时只返回一条。
7. 合并搜索后的分页与 `total` 正确。
8. 响应不包含 payload、Token、Cookie、Passkey、下载地址和内部地址。
9. 批量列表不产生逐资源外部请求。
10. 明确多集不显示“范围待确认”。
11. 季包、倒序和缺证据范围保持保护语义。
12. `未关联`、`等待评分` 和 `分析中` 映射正确。
13. 回车和搜索按钮触发同一搜索行为。
14. 手机端可直接比较季集、大小和核心版本信息。
15. 海报失败和超长标题不产生页面级横向溢出或循环重试。

## 10. 发布与回滚

推送后由 GitHub Actions 构建不可变 SHA 镜像，执行 amd64/arm64 烟测并提升 `latest`。发布验收必须核对镜像 revision 与提交完整 SHA 一致。

前端可回退到不读取三个可选字段的旧版本；后端字段均为可选，无需数据库回滚。若中文搜索出现口径问题，可独立回退媒体标题合并，保留原始标题搜索；不会修改 RSS 原始数据。
