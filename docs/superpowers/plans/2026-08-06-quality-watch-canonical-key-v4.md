# 质量观察规范键迁移与桥接 v4 实施计划

对应规格：`docs/superpowers/specs/2026-08-06-quality-watch-canonical-key-v4-design.md`

## 阶段 1：规范键基础与订阅解析

1. 扩展 `torra_subscription_keys.py`，提供明确的规范键生成、公开键校验和碰撞拒绝能力。
2. 扩展 `QualityWatchSubscriptionResolver`，返回 `canonicalKey`、`publicKey` 和内部 `subscriptionKey`；Torra-only 固定使用规范键。
3. 为本地优先、Torra-only、公开/规范输入、摘要碰撞、Torra 离线和完整列表缺失分别增加单元测试。
4. 保持 API 投影继续只输出公开短键。

## 阶段 2：启动迁移器

1. 新增独立规范键迁移模块，先只读规划，无待迁移时返回 0 且不备份。
2. 有待迁移或冲突时使用 SQLite backup API 创建备份并执行完整性校验。
3. 映射只接受公开摘要与 `torra_subscription_id` 一致的观察单元；规范单元键用 `make_unit_key()` 重建。
4. 扫描观察单元、RSS 匹配、provider 动作、调度游标和登记的 JSON 列；未知 JSON 引用或未知幂等键格式直接冲突。
5. 一个 `BEGIN IMMEDIATE` 内重新规划、校验指纹并原子更新业务列、登记 JSON、白名单幂等键、调度状态及成功审计。
6. 冲突或失败时回滚，写数据库外脱敏 sidecar 报告并抛出启动错误。
7. 覆盖无迁移不备份、成功迁移、重复运行 0 更新、双键冲突、摘要碰撞、JSON 未知位置、RSS 唯一键碰撞、审计失败和备份失败。
8. 补充 RSS-only 候选迁移：从 RSS 匹配和结构化季集证据重建单元键，不要求预先存在质量观察单元。
9. 对已确认失联、未触发下载的 RSS 匹配只归档关系并保留 `rss_items`；同一冲突计划重复启动复用首次备份和报告。

## 阶段 3：启动门禁与桥接 v4

1. 在 Private RSS schema 初始化后、桥接器和调度器注册前调用迁移器。
2. 迁移异常直接中止 `create_app()`，确保桥接写入和调度器不注册。
3. 将 `BRIDGE_VERSION` 升为 `4`，保留 v3 收据，摘要仅统计 v4。
4. 验证迁移后的相同 qB/Symedia 事实只推进已有规范单元。

## 阶段 4：调度、RSS 与手工动作统一

1. 调度器通过统一解析器合并本地订阅和 Torra 只读订阅。
2. 本地订阅和 Torra 分别返回采集确认状态；连接失败、解析失败或响应结构异常返回 `source_unavailable`，已有单元延后处理；只有对应来源完整列表确认缺失才产生 `subscription_missing`。
3. RSS 运行时复用统一解析器，内部匹配、回扫、评分和动作只保存规范键。
4. 手工洗版、手工 RSS 匹配和 provider action 主列/请求摘要改为保存规范内部键，公开 API 继续投影短键。
5. 调整兼容读取，禁止新写入公开短键但允许请求端继续提交公开短键。

## 阶段 5：端到端验收与文档

1. 新增 Torra-only → 桥接 v4 → 调度 → RSS 匹配/评分 → 质量面板集成测试。
2. 验证手工洗版和手工 RSS 匹配的新记录只含规范键，公开响应不泄露规范键或远端 ID。
3. 更新后端 README、DESIGN 和必要的 API 契约说明。
4. 运行专项测试、后端全量测试、前端类型检查和生产构建。
5. 运行 `git diff --check` 与 `verify-change`，确认本地 `mcc_data.db` 未修改、未提交。

## 完成标准

- 无待迁移时不创建备份；有迁移时备份先于写事务。
- 任何规范/公开双键、摘要碰撞、JSON 未知引用或唯一键碰撞都整批回滚并阻止启动。
- 内部新记录只保存规范键，公开短键仅存在于 API/UI 投影。
- Torra 临时离线不把观察单元误判为订阅不存在。
- v3 审计保留，v4 摘要和后续链路不重复。
- 完整生产链集成测试和全量回归通过。
