# 前端设计说明

## 模块职责

`src/` 是 Fluxa 的 React 工作台前端，负责发现、订阅、资源中心、任务、活动和设置等统一操作界面。影院大厅使用 Mineradio 提供的独立视觉资源和页面边界，不继承工作台的主题与布局规则。

页面通过 `src/services/api.ts` 访问同源 Python API。前端只负责展示状态和发起明确操作，不持有外部服务密码、Token、RSS 下载地址或写权限判断。

## 信息架构

- `components/pages/`：按用户任务组织页面和详情交互。
- `components/layout/`：导航、全局作品搜索、确认弹窗和跨页面框架。
- `app/urlState.ts`：统一地址参数写入、浏览器历史项和返回滚动位置恢复。
- `services/api.ts`：统一 HTTP 请求、超时与错误处理。
- `types/`：前后端公开响应类型。
- `styles/`：工作台、发现页和影院大厅分层样式。

工作台以宽屏电脑使用为主，同时保留窄屏可操作性。深色和浅色主题共享信息层级；浅色使用克制的 macOS 磨砂玻璃风格。弹窗和浮层必须支持键盘焦点、关闭恢复和减少动态效果。

追更页的互斥对账统计使用全库口径，不随电影/电视剧和其他列表筛选变化；摘要必须显示“全库构成（N）”。列表标题则跟随当前分类显示“电视剧 N 条”“电影 N 条”或“屏蔽列表 N 条”，避免与全库统计混淆。

## 跨页状态与全局定位

顶部全局搜索读取 `/api/v2/search`，合并本地追更、已识别 RSS、任务、当月日历与 Emby TMDB 索引；本地没有结果时才使用 TMDB 只读补充。标准 TMDB 结果进入作品生命周期总览；无 TMDB 的本地任务显示“身份待确认”，保留公开 `chainId` 并直接进入对应任务，不构造不可用的作品详情地址。

关键页面状态写入地址参数并监听 `popstate`：任务中心保存 `userState/completedDate/chainId/targetKey` 及高级诊断条件；日历保存 `year/month/view/type/status/q/date/detail`；资源中心保存 `view/q/sourceId/identityStatus/window/offset/publishedDate` 以及可选订阅、TMDB、媒体类型、季集和 `matchId` 精确上下文；追更保存媒体类型、关键词、年份、状态、更新时间、仅缺集条件与当前作品/季集。详情打开使用新的历史项，关闭优先返回上一状态；共享历史工具在离开前保存滚动位置，使返回列表时恢复原筛选与上下文。内部跳转必须使用 SPA 历史，复制当前 URL 可以直接定位同一筛选或任务。

## PT 获取主线

```text
发现内容 -> 本地订阅台账 -> Torra -> qBittorrent -> Torra 秒传 115 -> Symedia -> Emby
```

Torra 是第一阶段唯一 PT 获取入口。发现页和订阅详情中的“搜索资源”只调用 `GET /api/v2/rss-items` 查询本地 SQLite RSS 种子箱，用于查看候选证据，不触发下载、转存、订阅推送或其他外部写操作。

每个 RSS 来源可独立设置轮询周期。界面保留 1、3、5 分钟快捷值，同时允许输入 1–1440 分钟的自定义整数；后端执行相同范围校验。

订阅搜索会携带 TMDB、媒体类型、季号和年份查询本地种子箱：同一 TMDB 身份优先，缺少外部身份时才按标题与季号或年份保守兜底，错误 TMDB 不会混入结果。查询中、失败、无结果和结果列表直接显示在被点击的订阅条目内；发现页的同类结果插入被点击卡片所在网格位置，避免用户离开当前上下文。

订阅详情进入任务中心时携带订阅 ID、TMDB ID、季号和标题。任务中心按订阅 ID、TMDB ID + 季号、规范化标题逐级匹配；命中后显示该订阅的全部关联任务并聚焦第一条，未命中时明确说明订阅尚未形成任务。用户可随时退出聚焦并恢复普通筛选列表。

旧的 `/api/discover/resources/search` 作为后端兼容接口保留，但当前 React 工作台不调用它。115、Telegram、HDHive 和 MoviePilot 不属于当前资源搜索路径。

## 状态与安全边界

- 敏感字段仅显示“已保存”状态，前端不回显原值；只有重新输入才修改。
- 所有外部写操作由后端配置闸门最终判断，前端按钮状态不能代替服务端授权。
- `TORRA_PUSH_ENABLED=false` 时，保存订阅只进入本地台账，不应产生 Torra 后台排队或失败活动。
- Torra 第一阶段采用单向只读镜像；远端删除和双向冲突处理留到第二阶段。
- Torra-only 条目的 ID 是后端生成的不透明公开哈希；前端只原样传递，不能推导、缓存或显示原始 Torra ID。
- RSS 搜索结果不暴露下载 URL、Passkey 或 Cookie，只展示来源、标题、时间、大小、版本和季集信息。
- RSS 历史身份只通过显式“补齐身份”批量处理；GET 查询不写库，多候选保留冲突，唯一可靠匹配才补充 TMDB/IMDb。

### 2026-08-07 - RSS 资源卡片媒体身份与比较信息

资源中心只从已识别 RSS 的本地订阅、精确发现候选和现有 TMDB 缓存读取可选媒体标题、年份与海报；来源冲突或身份不完整时保持原发布名，不在卡片请求中访问外部服务。卡片保留原始发布名用于技术核对，媒体标题可参与同一搜索并在完整命中集合上去重、计数和分页。

明确的多集范围使用独立“明确多集”分类，不再冒充范围待确认。桌面和手机卡片分别使用 56×84 与 48×72 海报；图片失败时退回无图紧凑布局并记忆失效地址。手机端默认保留季集、大小和核心版本标签，普通站点资源使用中性“未关联”状态，搜索图标改为可提交且有可访问名称的按钮。

### 2026-08-06 - RSS 产物级人工精准下载

资源中心保留逐集评分，但按 `subscription + artifact` 展示唯一产物卡片；多集种子只有在覆盖的全部季集都获胜时才显示精准下载预检。卡片展开后展示集级结果，等待基线、身份或规则阻断、持续评分和确无升级分别使用不同空状态，避免把无基线误写成没有高分版本。

前端预检和确认只提交公开产物组 ID、10 分钟预览令牌与幂等键，不接收或修改 RSS 下载地址、保存目录、下载器或 qB 分类。确认弹窗只展示后端公开的覆盖范围、分数提升和分类配置状态；分类缺失时明确显示“未设置 · 按订阅目录提交”。设置页在实机验收前只提供“关闭/仅人工确认”，不开放自动执行。

### 2026-08-05 - 任务优先与缓存先行

首页不再重复展示关注项和站点原始流量，四个主卡固定为“今日入库、正在下载、等待自动恢复、需要处理”。异常卡按“对象、原因、影响、下一步”展示一个主要动作；组件名、Hash、路径和上游原文只在任务技术详情出现。

### 2026-08-04 - 本地产品闭环收口

日历页面只读 SQLite 月快照；缓存缺失或过期时显式排队后台刷新并轮询同一 GET，不在页面请求内重算。追更页增加独立“对账待处理”筛选，`conflict/remote_missing` 不再混入媒体下载/入库异常。

资源中心把普通标签明确为“追更待识别”。待整理视图同时展示有效、失效和冲突归属，只有“订阅不存在”的失效匹配可通过预览和确认归档；归档保留原始 RSS 与评分证据。公共 `PosterImage` 对同源代理图做保守 16×24 空白检测，缺图、透明空图、纯白无效图统一显示标题占位，并在当前应用生命周期内记忆失败地址；日历复用同一组件。

### 2026-08-02 - 首页缓存确认状态与自动化文案

首页继续读取原 `/api/v2/home/summary`，但数据改由后端模块缓存提供。页面可选读取每个关注项的 `confirmation/unconfirmedCount` 和模块新鲜度：下载完成未入库、追更缺集同时显示已确认值与暂未确认对象；某一模块失败时保留其他模块和上一份可靠值，真正成功返回的零仍显示 0。刷新按钮只重读缓存，不触发实时全链路汇总。

### 2026-07-31 - 资源中心四个工作视图（已由五视图口径替代）

`reviewState`、`groupState` 和候选组 `counts` 都是公开契约的可选增量。旧请求继续返回原分页结构，非法筛选继续返回 422；所有读取保持只读，不触发 Torra 搜索、下载或其他外部写操作。390px 及以下使用 2×2 稳定分段布局，深浅主题共享工作台变量。

### 2026-07-30 - RSS 精准下载只读预检

高分冠军增加“精准下载预检”，前端只把公开匹配 ID 放在路径中并提交 JSON 空对象。预检结果展示 Torra 正式能力缺口及其他阻断数，不提交规则 ID、下载器、分类、目录、标签或 RSS 地址，也不创建下载动作。旧“人工 Torra 分析”继续作为会触发整订阅搜索的独立兜底，不与精准预检合并。

当前 Torra 未提供订阅绑定的指定 RSS 资源入口，因此页面固定表达“精准下发不可用”，不会出现可确认下载按钮。结果刷新只保存在当前页面内，候选组重新加载时清空；按钮、错误和诊断文字继续使用工作台主题变量，深浅主题保持可读。

### 2026-07-23 - 阶段 H 状态可信度与 RSS 收口

任务链新增独立 `identityState` 和 `executionState`，未识别身份下的推断停滞显示为“疑似阻塞”，明确失败仍保持“需要处理”。普通任务卡只显示 `userReasonText`，完整路径、Hash 和上游错误进入技术详情。日历新增“正常保护”和“状态未知”，只有明确追更范围、超过允许延迟且没有有效证据的剧集才显示“逾期未获取”。移动五项导航与日期按钮达到 44px，月/周视图不再依赖桌面宽网格。发现卡片的失败海报使用中性图标占位，追更小海报继续使用紧凑首字占位。

### 2026-07-22 - 五态组件与 qB 安全操作

首页、任务中心和追更改用同一五态组件，固定正常、等待、正常保护、暂未确认和需要处理的图标、文字与颜色，页面不再自行定义状态色；底层状态码仍为 `evidence_insufficient`。qB 暂停/恢复增加只读服务端预览，返回动作资格、影响对象、禁止原因、确认要求、幂等键和冷却时间；确认执行时复查状态并拒绝旧预览，完成后继续读取真实状态并写入脱敏活动日志。Emby 刷新沿用已有的新入库证据、10 分钟冷却、并发锁、手动确认、执行前复查和同证据去重边界。移动端固定首页、发现、追更和任务中心四入口，任务摘要改为 2×2，长任务标题保留两行。未新增其他外部写能力。
